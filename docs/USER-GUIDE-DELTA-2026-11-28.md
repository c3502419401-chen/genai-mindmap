# 用户手册 × 实际界面：差异清单（2026-11-28）

对 `docs/USER-GUIDE.md`（实测 **626 行**，任务单里记的是 534 行——手册已经扩写过）逐条照做，
用真浏览器（Playwright + 本机 Chromium，1440×900）核对。下面每一条都是"手册说 X / 实际是 Y"，
能复现的给复现路径，不能复现的标"待复核"。

**判定口径**：`✅ 一致` / `⚠️ 措辞或位置不同但功能在` / `❌ 照做走不通`

---

## A. 会挡住人的（按严重度）

### A1 ❌「第 3 步：写主题（可以不写）」

- **手册**（第 51–59 行）：标题写"可以不写"，正文写"**不写会怎样**：用材料标题当中心主题。实测输入框下面会直接说明：
  「没写主题：用材料标题「campus-garbage-sorting」当中心主题。」"
- **实际**：材料就绪（「文本 · 649 字」）但主题为空时，**「生成导图」是 `disabled`**；写一句主题后同一按钮立即可用。
  界面上没有任何一句解释"为什么按钮是灰的"。
- **复现**：粘 649 字正文 → 不加主题 → 查看「生成导图」`disabled === true`（截图 `acceptance-shots/01-06-ready.png`）。
  对照：`fill("数据结构与算法")` 之后 `disabled === false`。
- **影响**：手册第 3 步的"可以不写"这一整段（含那句提示语）在当前版本**走不到**。

### A2 ⚠️→❌「第 2 步：传文件 · 点 `+` 会直接弹文件框」

- **手册**（第 39 行）："点对话框里的 `+`。会直接弹出系统的文件选择框。可多选。"
- **实际**：`+` 确实弹系统文件框（真实 `filechooser` 事件触发，`accept` 覆盖 pdf/docx/…/md/wav/png…）。
  **但**：选完一个 548 字 `.md` 后，3 次实测里 **2 次**停在「文档 · 正在解析…38 秒」，
  `合并后 0 / 300000 字（含分隔换行）`，没有「已就绪」「彻底删除」，「生成导图」禁用并提示
  「来源正在解析，请等待完成后生成。」；第 3 次 3.1 秒就完成（「已就绪 · 550 字」）。
  同一个文件直接 `POST /api/ingestion/files` 只要 **20 ms** 返回 `status: "parsed"`。
- **手册缺的**：没有"解析要等多久 / 卡住了怎么办"。

### A3 ⚠️ 材料缩略块与入口的文案

| 手册 | 实际 |
|---|---|
| 缩略块显示「正在解析…」→「**文档 · 1029 字**」 | 缩略块显示「文档」+「**正在解析…N 秒**」（带秒数）；就绪后字数在**材料面板**里（「已就绪 · 550 字」） |
| 点缩略区右侧的「**管理材料**」→ 打开面板 | 按钮实际叫「**管理材料 · 1 份**」；而且**上传/粘贴后材料面板会自动展开**，按钮当场变成「**收起材料 · 1 份**」，不需要再点 |
| 面板里有「粘贴材料正文」→「**添加文本到来源**」 | ✅ 一致，两个都在（「添加文本到来源」在正文为空时是 disabled） |

### A4 ⚠️ 粘贴正文后的那句提示

- **手册**：粘贴后输入框里留一句「这段正文（N 字）已经放进材料，主题框里说要它做什么。」
- **实际**：✅ 这句逐字存在（有 510 ms 的反应时间）。**但**底部另有一句手册没写：
  「正文已经当材料了：写一句要它怎么整理，不写就用材料标题当中心主题。」——而按 A1，"不写"其实走不通。
  另外多出一个按钮「**放回输入框**」（把材料退回成正文），手册没写。

### A5 ❌ 生成进度文案完全不是手册写的那句

- **手册**（第 76 行）："进度行写「正在生成 · **已写完 7/7 章的子树** · 8 秒」这样的字样。"
- **实际**（实测一条完整时间线）：
  `正在生成 · 正在连接 · 1 秒` → `正在生成 · 正在定框架 · 4/7/10/13 秒` → `正在生成 · 正在给 63 个节点写说明… · 19 秒`
  → `正在生成 · 模型正在思考，已等 10 秒 / 20 秒` → `正在生成 · 已定好框架 · 46 秒`。
  没有"已写完 N/N 章的子树"这种句式。

### A6 ⚠️ 生成要等多久

- **手册**：本机实测 649/1029 字 → 64 节点，**30–40 秒**；P50 31.3 s / P95 41.4 s。
- **实际**：同一份 649 字材料 **5 次**：39.5 / 47.6 / 48.6 / 48.7 / 50.1 秒，节点数 **50 / 52 / 59 / 71 / 82**。
  没有一次落在 30–40 秒区间；全部 ≥ P95 口径。把"30–40 秒"写进手册会让用户以为卡死。

### A7 ❌ 第 7 步「看懂画布」漏了一条常驻横条、也漏了"视图是偏的"

- **手册**：右上「显示 40 / 64 个节点」、节点右上角小数字、右下 `+N` / `−`、右上「适应宽度 / 全图」，"默认是适应宽度"。
- **实际**：以上都在（格式一致），**另有**一条常驻横条手册没写：「**只显示了一部分 · 拖动可平移（还有 31 个节点在视野外）**」。
  更关键：**落地那一刻视图不是"适应宽度"状态**——40 个已渲染节点里只有 14 个在视口内，多个节点 `y` 为负（在视口上方）。
  用户必须自己点「适应宽度」或拖动。手册说"默认是适应宽度"与实测不符。

### A8 ⚠️ 第 8 步引用四步：功能对，细节两处

| 手册 | 实际 |
|---|---|
| 点角标 → 「来源引用（2）」每条形如「文档 · campus-garbage-sorting.md · 第 423–432 字」 | ✅ 结构一致；粘贴材料的来源名是「**文本 · 来源 1**」，行文是「文本 · 第 30–57 字」 |
| 点一条 → 原文抽屉「第 423–432 字 · 共 1,029 字」 | ✅ 一致（实测「第 30–57 字 · 共 649 字」） |
| 点「看上下文」→ 前后各 600 字，按钮「再读上文 / 再读下文」，贴到两端时消失 | 材料 649 字时**全文一次载入**，按钮直接变成「**收起上下文**」，没有"再读上文/下文"。手册没写这个态 |
| 高亮准不准 | ✅ **准**：高亮段与引文逐字对应（`70-06-context.png`） |

### A9 ⚠️「检查与建议」要点两次，"修复"实名"一键修复"

- **手册**（第 330–332 行）："当诊断里有能自动修的三类时，诊断面板会出现「**修复**」按钮，旁边写「同级重名 2 处、单子节点 3 处」"；
  第 8 节"点「检查与建议」→ 看报了什么"。
- **实际**：第一次点只打开面板、写「**还没检查过。点「检查与建议」跑一次：结构问题、修改建议、引用能否核验，一次给全。只读，不改任何东西。**」，
  要再点「重新检查」才出结果；结果是「检查与建议 · 1 条建议 · 1 条提示」+「**可自动修复** · 单子节点 1 处，共 1 处」+「**一键修复**」+「改完可整体撤销」。
- **另一处容易混**：落地状态行的「**N 条诊断**」按钮打开的是"本次生成明细"（里面有 19/20 条"没有可核验的原文引用"），
  而底部「检查与建议」是结构检查。两处措辞相近、内容不同：一个说"20 条诊断"，另一个可能说"没有发现问题"。

### A10 ⚠️ 7.1 保存：入口在，但要滚；`Ctrl+S` 不可靠

- **手册**：`Ctrl+S`，或 `☰` →「操作」→「保存」（"实测抽屉里还写着快捷键提示"）。
- **实际**：
  - ☰ 抽屉里确实有「操作 / 保存 / 新建 / 演示示例 / 知识库 / 导入 / 导出…」。**但**该抽屉先铺 26 条历史导图，
    1440×900 首屏**看不到**这一整块（实测这些元素 `y > 852`，在抽屉可视区外），必须滚动。手册没提"要滚"。
  - `Ctrl+S`：两次实测，一次成功（「已保存，版本 1。」），**一次完全没反应**（状态行不变）。
- **另**：顶栏确实没有保存按钮（与手册一致）。

### A11 ⚠️ 7.4/九.2 只说了"删限主"，没说"保存也限主"

- **手册**（7.4）："删的是**别人的图** → 不会发生：读是共享的、**删是限主的**"；九.2：「别的账号能看不能改」。
- **实际**：换个游客打开同一张图后保存，`PUT /api/mindmaps/{id} → **403**`，界面写
  「这张导图不是你创建的，只有创建者能改。想保留自己的版本，可以用「**另存为**」新建一份。」
  —— **「另存为」在界面上找不到**（`☰` 抽屉、历史列表、右抽屉都没有），手册也没提这个按钮。
  联动 A10：`Ctrl+S` 那次"没反应"，很可能就是撞上了 403 而界面只把话写在一个不显眼的状态行上。

### A12 ✅ 7.4 删除：逐字对得上

「删除导图」→「确认删除」+「彻底删除这张导图，连同它的改动记录。不可恢复。」
→「已删除导图「…」，连同它的改动记录，不可恢复。画布已清空。」——与手册一致。

### A13 ⚠️ 5.2 拖动：四方向与断关系的提示都对，但有一处没写

- ✅「成为「中心主题」的子节点」（落地后坐标真从 `(1098,420)` → `(720,637)`）
- ✅ 拖到空白：「断开「叶子甲」与「第一条分支」的关系 · 成为一级分支」→「已把「叶子甲」从「第一条分支」下面断开，
  挂为一级分支（第 4 位），可撤销。」
- ❌ **拖"一级分支"到空白处完全无反应**（不写状态行、不给提示）。手册没说这个区别，用户会以为拖坏了。

### A14 ✅ 六、快捷键三条状态行逐字一致

「已加子节点，输入文字后按回车确认。」/「已加兄弟节点，输入文字后按回车确认。」/「已删除该节点及其子节点，可撤销。」/「已撤销。」

### A15 ⚠️ 六·五 账本：文案对，但"账本只记生成之后"这句手册没写

- **实际**：打开一张非本次生成/导入的图 → 「改动记录」里「**还没有改动记录**」
  「还有未保存的改动。保存之后它们才会出现在这里。」「这张图还没有任何改动记录。**导入的图一条都没有——账本只记生成之后发生的事。**」
  「共 0 条事件 · 这里 0 行」。手册的示例表里都是"有记录"的样子，没写这个空态。

## C. 数字口径要改的（手册里当承诺写的数）

| 手册 | 实测（同一份 649 字材料） |
|---|---|
| 64 个节点 | 50 / 52 / 59 / 71 / 82（5 次） |
| 引用覆盖 47/64 = 73% | 33/50 = 66%、36/52 = 69%、79/82 = 96% |
| 落地 30–40 秒，P50 31.3 s | 39.5 / 47.6 / 48.6 / 48.7 / 50.1 秒 |
| 首帧 0.09 秒 | 我 1 秒轮询只能证明 ≤1.07 秒（这一项不构成反驳） |

**结论**：这些数在手册里被写成"实测值"是可以的，但被当成"承诺值"（"64 个节点时字会小到看不清"、
"一次生成总有 1/5 到 1/3 的节点拿不到引用"）就站不住——同一份材料同一台机器，节点数漂 64%、
覆盖率漂 30 个百分点。

## E. 一致性小结

- 手册里**逐字对得上**的：第 2 步粘贴提示、第 5/6 步落地状态行、第 7 步画布读数格式、第 8 步引用四步、
  5.2 拖动四方向与断关系、六、快捷键三条状态行、7.4 删除两段式、8④「从本轮移除 / 彻底删除」那行对照说明。
  —— 这些是手册写得最扎实的部分。
- 需要改的：**A1（主题必填）、A5（进度文案）、A7（落地视图）、A9（检查点两次 + 一键修复）、A10（保存要滚 + Ctrl+S）、
  A11（保存限主 + 另存为不存在）**。
- 需要补的：B1–B10，尤其 **B1 恢复条**（用户刷新后最容易懵的一处）。

> 复现脚本按 `D:\_acc-playwright\*.mjs` 那套写法（`playwright-core` + 本机 Chromium `executablePath`），
> 依赖装在项目之外的隔离目录，**没有写进 `frontend/package.json` / `devDependencies`**。
> 关键脚本：`03-realpaste.mjs`（真剪贴板）、`10-e2e3.mjs`（完整路径）、`11-drag-check.mjs`（拖动/检查）、
> `14-unlink.mjs`（断关系）、`18-stuck.mjs`（上传卡解析的网络时间线）。
