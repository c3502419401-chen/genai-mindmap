# 实体消解入口设计

入口先预览，再由用户选择具体的别名对并提交。预览不创建别名、不修改材料或证据；它以只读方式复用已有向量缓存，未命中的名字调用向量服务但不写入缓存，产生的额度和等待时间在按钮附近告知用户。为控制单机成本，最多比较 500 个名字，其中最多 100 个席位留给最近入图的名字（包括孤立实体），其余优先选关系多的名字；空结果不代表完整图谱没有候选。候选是算法建议，不是事实或语义证明。

## 接口与状态

- `POST /api/knowledge/aliases/candidates` 创建只读预览，立即返回任务 ID；`GET /api/knowledge/aliases/candidates/{job_id}` 返回阶段、终态和候选；`DELETE /api/knowledge/aliases/candidates/{job_id}` 取消或丢弃预览。
- 任务只保存在当前后端进程的有界内存中：同一时刻最多一个候选计算，结果限时保留，过期或进程重启后须重新预览。这样不引入常驻索引、数据库迁移或多 worker 写入假设。任务只含必要的候选及短摘录，不写日志或持久化；轮询不会产生图库写入。
- `POST /api/knowledge/aliases/apply` 只接受任务 ID 和用户勾选的候选 ID。服务端从该次预览取回原始候选，不接受客户端伪造的名称、分数或依据；无效、过期、已用、重复或未完成的预览被拒绝。写之前重新核对所选摘录、图边坐标和别名表，变化时要求重新预览；写入仍由图存储单事务的成环检查负责。材料存 SQLite、关系存 Neo4j，两者之间没有跨库事务，其他操作仍可能在检查后改变材料或图。
- 当前单进程内的应用、逐对删除和清空通过同一把锁串行；校验与写入处于同一图事务。直接绕过本服务写 Neo4j 的外部进程不受这把锁保护，预览校验不是跨进程的可串行隔离。

## 候选、出处与确认

一组候选拆成逐对选择。预览不把整组所有名字直接挂到组主名：对算法实际判定通过的边，先按判定层级和强度构造最大生成树，再从组主名向外逐边列出别名与主名。这样每个建议对都有自身直接通过的判据，且每个别名最多一个待选指向；选其中一对不强制选整组。每对展示自己的分数及单位：构词判定是长度比，向量判定是余弦。树上的边可能仍然是错合，出处也不能证明语义相同。两端优先回查图的证据边，在持久材料中按坐标取原文短句，并核对实体名确实出现在摘录中。孤立实体没有图边坐标：对缺失的名字，最多扫描最近 100 篇材料的前 5 万字，逐字找到名字时标为「知识库原文匹配，未记录图谱出处」，绝不声称这是实体的抽取来源。仍找不到时明确显示出处不可核验，也不允许选择该对；超过扫描范围不等于材料里一定没有。用户可逐对选或全选有出处的候选，默认不选择；应用前列出数量与名称，明确说明查询路径会变化，确认后才写。

## 进度与取消

前端定时轮询，显示读取图谱、计算向量与候选、回查出处等真实阶段，以及完成、取消或失败；不编造百分比。向量批次不可用时停止后续批次，保留已有向量并继续构词比较；任务与界面显示有向量的实体数及可能漏候选的警告。向量未配置、图谱连接失败与空结果各自显示。取消立即使任务不可应用，正在执行的外部请求无法强制中断：它返回后丢弃结果，计算线程退出前不再接收新任务。关闭页面不等于确认；未应用的结果到期自动丢弃。

## 撤回与限制

图库的消解只添加 `ALIAS_OF` 边，不搬动 `REL` 证据或删除实体；现有逐对删除接口可以撤回该别名关系，界面在结果里提供具体删除入口。预览会排除已存在的同一别名对，避免把旧关系误报为本次创建。同名不同类型会生成多条同名关系，逐对撤回会删除该名字对当前的全部别名边；如果其他操作在应用后又给这一对添加了边，撤回也会删掉它们。撤回不回滚其他图库修改或已经生成、保存的导图。原始证据能证明摘录出自材料，不能证明两个名称语义上确为同一实体；同名不同类型和传递分组尤其需要人工判断。

## 判据的边界：否定前缀、拉丁标识符与合称

构词判据只有一句话：短名是长名的顺序子序列、长度比过闸、短名里有一整块连续字、并且没有丢掉类型词。它在"加限定词"这一种构词方式上成立（`雨污分流改造` ⊂ `城市雨污分流改造`），在另外两种上不成立——而这两种的错合都像真的：材料里两个名字都出现过，出处、坐标、摘录一样成立，看不出问题。真库（363 个实体、78 条候选）上这两种占了一半，修完之后是 54 条。

**否定 / 取值标记**：长名比短名多出来的那段字里若含「无 / 不 / 非 / 反 / 未 / 半 / 零 / 伪」或拉丁前缀 `un- non- anti- dis- mis- in- im- ir- il-`，直接判为两个概念（`监督学习` 与 `无监督学习`、`化石能源` 与 `非化石能源`、`学校群体` 与 `学校的非正式群体`）。词表里每个字都要有真库命中才留：「准」曾经在表里，可它在「标准」「精准」里出现得比在否定里多得多，会把"多一个修饰词"误判成"多一个否定"，已删除；同时把「标准」补进 `DOC_TYPE_WORDS`——它和「办法」「条例」同属文件类，`可再生能源` ⊂ `可再生能源标准` 因此由类型词那一闸挡，理由正确。

**拉丁标识符**：代码符号、配置键、文件名不是由"取字"构成的，一个字符之差就是另一个东西（`mindmap_llm_mode` / `mindmap_llm_model`、`revision` / `baserevision`、`ai` / `api`、`source` / `search_sources`）。这一类只认归一化后完全相同：去掉包在尾部的括号引号（`execute()` 与 `execute`）、只取路径最后一段（`stores/mindmap.ts` 与 `mindmap.ts`）、统一大小写。**不做**单复数与版本归一——`source` / `sources`、`pydantic` / `pydantic v2` 在代码里是两个符号。两三字符的纯拉丁短名（`AI` / `API` / `SSE` / `RAG`）等同于中文泛称，不做任何名字的别名。

**合称提示**：长名如果是"短名 + 库里另一个实体名"首尾相接拼出来的（`碳达峰碳中和` = `碳达峰` + `碳中和`），候选仍然可选，但带一句提示（`notice` 字段，界面显示 ⚠）。排除它会误伤「城市」+`雨污分流改造` 那种同一事物的两种写法，静默放过又会让两项政策合成一项，而两份材料里本来就同时写着这两个词——事后看不出错。所以它进候选，人看一眼。

判据只在这一层收窄，落库与撤回的口径不变：仍然是逐对确认、仍然可以逐对删。
