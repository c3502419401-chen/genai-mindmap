# 折叠退休：为什么"折而不裁"最后还是把内容拿走了

`tools._fold_tree` 已从生成链路删除。超过**可读性参考值**（`INITIAL_MAX_NODES = 80`）
只记一条 info 诊断（`TREE_OVER_READABILITY`），树上**一个节点都不动**；**承载能力**
（`MAX_TREE_NODES = 1000`）本来就由契约在 `_validate` 那一步管。可读性交回渲染层。

## 1. 用户看到的两件事

    ① 折叠节点的标题没有信息量：「其他 3 项」——被折叠后会看不到原本的内容
    ② 点「展开」拿不回原来那几个

第 ② 条是结构性的，不是笔误：`_rollup_node` 造出来的聚合节点是**叶子**
（`children=[]`），被并的那些兄弟连同它们整棵子树都不在树里了。界面上那个"展开"
按钮走的是 `node_expand` → **模型重新生成**一条新分支，与原来那几个没有关系。

## 2. 同一棵树上的对照（真 DeepSeek，无材料、外部检索关）

三批独立生成，"折"与"不折"打在**同一棵**树上（把 `_fold_tree` 换成恒等拿到不折的树，
再在本地按 `FOLD_CAPS=(8,4,2)`、`limit=80` 原样跑一遍）：

| 主题 | 不折叠 | 折叠后 | 折叠节点 | 被吞掉的节点 | 一级分支 |
| --- | --- | --- | --- | --- | --- |
| AI 学习 | 85 / 8 支 | 47 / 5 支 | 「其他 4 项」 | **38** | 8 → 5 |
| 多智能体写作系统的架构取舍 | 88 / 7 支 | 54 / 5 支 | 「其他 3 项」 | **34** | 7 → 5 |
| 某个项目的记忆系统设计 | 98 / 9 支 | 49 / 5 支 | 「其他 5 项」 | **49** | 9 → 5 |

分母是"超出 80 多少"：三批分别是 5 / 8 / 18 个。**为了少 5–18 个节点，拿走了 34–49 个。**

第四批（同主题、说明段真跑）：结构那一段给到 **157 个节点 / 8 条一级分支**，第三段
145 个节点分成两半并发，各 65.4 秒、合计 16,555 字，整次生成 116.8 秒。也就是说真实
生成常在 80–160 这个量级——折叠不是"偶尔收窄一下"，它把绝大多数树砍到一半以下。

本机库里那棵树更好认：`run-mwvnxcnl-…`（22 个节点 / 5 个折叠节点）的根下第三支就是
`其他 3 项`，`detail` 写着「含：校园AI活动；能力与科研成长；机构与人物。」——三条一级
分支、连同它们各自的子树，被换成了一行字。

## 3. 机制上为什么必然走到这一步

`_fold_pass` 的判据是 `len(kids) > cap + 1`，`_fold_tree` 的外层是
`while _count_nodes(root) > limit`，`FOLD_CAPS` 是 8 → 4 → 2 的阶梯：

- 超出 5 个节点，cap=8 那一趟多半折不动（真实树的扇出常在 3–8），于是降到 cap=4；
- cap=4 在**根**上做的第一件事就是 `kids[4:]` —— 后 4 条一级分支整体收进一个节点；
- 折完立刻 ≤ 80，循环结束，`_clip_tree` 那道兜底根本轮不到。

所以"阶梯"不是"逐步收窄"，是"一次跳到最狠的那一档"。第二条硬伤是不可逆：rollup 是
叶子，`detail` 上限 2000 字只放得下列表，`source_refs` 取并集后撞 20 条上限（用户那棵
的 `其他 3 项` 就是 20 条），展开、保存、导出都恢复不出原结构。

## 4. 三条替代路线当时各自卡在哪（§一 的结论）

**A：塞进 `Node` 的某个现有字段。** 不可行。`Node` 的全部字段是
`id / label / children / note / detail / expandable / collapsed / color / icon / style /
role / source_refs / pos`，而 `model_config = ConfigDict(extra="forbid")`——没有自由区。

- `collapsed` 是 `bool`，只能表态，装不下一棵子树；
- `detail` 是**正文槽**（≤2000 字，界面上按"说明"分区渲染，标题槽取 `note or label`），
  把子树序列化进去既放不下（三支 × 每支十来个节点 + 引文远超 2000 字），也会被当成
  说明文字显示出来；
- 顶层同样没有自由区：`ContentBase` 也是 `extra="forbid"`，只有
  `schema_version / title / theme / relations / source_usage`。

**B：不真折，节点都留着，只在渲染时默认收起。** 数据层最干净，但当时
`frontend/src/stores/mindmap.ts` 是禁区，而视图的唯一入口就在那里：`flatten()` 建
`store.nodes`、`layoutDiagram` 也在 store 里算，`MindMapCanvas` 只吃 `store.nodes` 与
`store.edges`。组件层拦不住（拦一半会和布局/连线分家）。

**C：被折的子树存到后端别处，展开时读回来。** 三处都被挡住：`runs.candidate` 会被
最终树覆盖；加一列要动 `app/mindmaps/repository.py`；加一个还原接口要动
`app/agent/router.py`，而接口一变 `openapi.json` 就得重生成。

**D：不折，完整树交给前端。** 选它。理由不是"三条都太重所以将就"，而是：树上一共
85–157 个节点，对契约（1000）和渲染（库里有一棵 561 节点的图）都是小事，对用户只是
"要缩一档看"；而 A/B/C 三条**都是在替用户决定他看什么**——这正是他抱怨的那件事。

## 5. 代价（这一半也要说清）

- **第三段要多写被折掉的那些节点。** 折叠发生在 `_fill_details` 之前，被折掉的节点
  连说明都不写，所以它还兼着"说明阶段的工作量闸门"。实测 157 节点的树：145 段说明、
  两份并发各 65.4 秒、16,555 字。折叠掉的 38–49 个节点原本会省掉其中一部分。
- **标题概括若走模型档**：一条批量调用（5 组一起）实测 **1.87 秒**，输出可用
  （「校园AI活动与科研成长」/「AI学情应用与教师定位」/「提问技巧与工具组合」…）；
  逐组各调一次约 9 秒。**这一条现在用不上**——没有折叠节点就没有要概括的对象；留着
  这个数是为了下一轮"视图层收起"真要做分组标题时不至于凭感觉估。

## 6. 可读性归渲染层（下一轮，禁区已解除）

要点只有一条：**数据一直是完整的，只是默认不把 157 个节点全摊在屏幕上。**

- `stores/mindmap.ts`：`flatten()` 与 `layoutDiagram` 是唯一入口。收起 = 在那里按
  "已展开层数 / 每组前 N 个"过滤；节点仍在 `content` 里，保存、导出、撤销栈一个字节
  都不受影响（这也是它与折叠的根本区别：折叠改数据，收起只改视图）。
- `canvas/MindNode.vue`：加一个折叠箭头 + 「还有 N 个」徽标。注意别和 `Node.expandable`
  混起来：三态说的是**模型还能不能再长**，视图收起说的是**这一屏默认摊开多少**。
- `Node.collapsed` 已经在契约里（FreeMind / JSON 导入都会写它），但**现在只被透传保存，
  没有任何渲染读者**——视图收起正好用它做持久化。
- 验收判据已经有一条现成的：`canvas/clarity.ts::chooseViewMode` 算出的 `fit-all` 缩放
  与字号。157 节点的树在 1600×900 上会掉到 4–5px，那就是"看不见"，应该由收起而不是由
  删节点来解决。

## 7. 这条路上还剩什么（读代码时不要被旧注释骗）

| 东西 | 现在是什么 |
| --- | --- |
| `INITIAL_MAX_NODES = 80` | 纯**可读性参考值**：`data["node_limit"]` 与诊断文案用它 |
| `TREE_OVER_READABILITY` | info：超参考值只报数，节点一个不少 |
| `TREE_CLIPPED_TO_CONTRACT` | **不存在了**：越过 1000 的产物在 `_validate` 被整棵拒（`invalid_map`） |
| `partial` | 只在输出被截断（`SalvagedOutput`）时为真 |
| `cut_nodes` | 这条路上恒 0；键留着只是为了与 `mindmap_generate_deep` 的 data 同形 |
| `_clip_tree` | **没有生产调用方了**，留着 + `tests/test_branch_budget.py` 是"为什么不该按前序砍"的可执行反面证据 |
| `_fold_tree` / `_rollup_node` / `FOLD_CAPS` / `FOLD_LABEL` | 已删除 |

读数的复现脚本本来是本目录下的 `_fold_probe*.py`（一次性探针，已随这次提交删掉）；
要重跑同样的对照，做法是：把 `tools._fold_tree` 打回恒等拿不折的树，再对同一棵树跑
一遍旧算法——两个数都写在 §2 的表里。
