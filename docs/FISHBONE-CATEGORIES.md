# 鱼骨图的类别：为什么可以按主题定，以及凭什么不退化

`MINDMAP_FISHBONE_FREE_CATEGORIES`（默认**关**）。关着时 `FISHBONE_PLAN_PROMPT` 与
`FISHBONE_TREE_RULES` 与 `a290555` 那一版**逐字节相同**（整份文本的 sha256 钉在
`tests/test_fishbone_categories.py` 里）。

## 1. 为什么要改

5M1E（人 / 机 / 料 / 法 / 环 / 测）来自**制造业现场管理**。对着「为什么团队协作效率低」
「为什么客户复购率上不去」这类主题，那六个维度本来就不合适，而改之前的提示词明令
"一级分支**必须正好是这六个类别**，不要改写成别的话题分类"。

模型于是硬塞。实证的那张图（主题是人的管理）：六类都在，而「料」下面写着「员工技能
不足」——那是「人」里的东西。**那不是模型不会分，是它没有第二个出口。**

## 2. 三种自由度，选了哪一个

`A 完全自由`：三条判据（下面第 3 节）一条都不写，只让模型"按主题定 3–6 个类别"。
风险是真的——改之前的提示词那句"不要改写成话题分类"就是在防它，而放开类别名之后，
"话题分类"与"原因维度"的界线只剩模型自觉。**A 不是"更自由"，是"没有判据"。**

`B 模板选择`：给一套模板（5M1E / 服务业 / IT / 8P…）让模型选一套。有依据，但覆盖面
天生有限：模板是别人整理好的，而真实的主题（⑤推荐算法准确率）落在任何一套模板之外。
更实际的问题是 **8P 有 8 根骨，而契约上限 `MAX_FISHBONE_BONES = 6`**——选 8P 只能截断，
那不是照用户的模板画。

`C 半自由`（**选中**）：类别名自由，但三条硬约束都写进提示词，并且给**可判的界线与
正反例**。C 与 A 的差别不是"约束多少"，而是"关掉的那条禁令有没有替代品"。

## 3. 「原因维度」与「话题分类」的可判界线

不能用"类别名像什么"判——「人」既是话题也是变量，「管理」既可以是维度也可以是职能。
可判的是**它是不是一个能取高低值的变量**：

> **原因维度是一个能取高低、有缺无的变量；话题分类是一个领域或职能。**

三个可操作的测试，都写进了提示词：

1. **因果槽位**：「（这个维度）不足 / 缺失 / 偏高 → 主骨上那个为什么」成立吗？
   「工具 → 效率低」成立；「人员管理 → 效率低」不成立（它不是一个变量，是一个题目）。
2. **还能不能再分**：「工具」下面挂的是具体原因（"审批系统要来回切三个页面"）；
   「人员管理」下面挂的是**另一个维度**（"招聘慢""培训少"）——那说明它是领域。
3. **正交性**：一个原因只能落进一个维度。「工具」与「系统」两份就是重复。

提示词里配了四组反例（领域名 / 已经是原因的名字 / 同义重复 / 全在同一面），因为改之前
那条提示词本来就是靠正反例工作的——只有禁令没有反例时，模型会挑一个最像的照做。

## 4. 覆盖面：丢掉的那件事，用另一条约束补回来

类别自由之后，"六个固定维度逼你想全面"这个约束就没了。补它的是**覆盖面约束**：

> 四个成因面里**至少覆盖三个**（名字随主题起，不要照抄）：
> ① 谁来做（人的技能、认知、意愿、编制）；② 用什么做（设备、材料、技术、数据、工具）；
> ③ 怎么做（流程、方法、规则、标准、职责边界）；④ 在哪做（环境、外部条件、时间、资源）。

这四类就是 5M1E 去掉"测"之后剩下的四类，也是 8P、服务业模板都能归进去的最小公约数。
**它保住的正是鱼骨图真正值钱的那件事（逼你把成因面过一遍），丢掉的是"永远是那六个
名字"——而后者在非制造主题上本来就没有兑现过。**

## 5. 用户能不能指定类别

**改之前：没有这条路。** 三处都查过：

- `AgentRunRequest`（`app/agent/contracts.py`）只有 `goal` / `intent` / `diagram_type` /
  `prefs_applied` 等字段，**没有类别字段**；
- `prefs` 里只有 `diagram_type`（`app/prefs/style.py` 的 `("diagram_type", "fishbone")`），
  没有类别；
- `diagram_intent.infer` 只认图型词（鱼骨图 / 思维导图 / 流程图）。

后果是用户说「按 8P 画鱼骨图」时，"8P"会被当成主题的一部分进 prompt，然后被
"必须正好是这六个类别"覆盖——**用户的话被静默吞掉，产出的还是 5M1E 六类。**

**这次一起加了最小的一条**：开关打开时，`named_fishbone_categories(topic)` 按词面认出
用户点名的那套类别（`5M1E` / `人机料法环测` / `人机料法环` / `4M1E`），写进 user 末尾
一句"一级分支**逐字就用这一套**，不要自己另立"，并压过模型自定。

三条边界写在代码里：

- **认不出来就什么都不加**（与 `diagram_intent` 同一条规矩：猜一套类别比让模型按
  `problem` 自己定更糟）；
- 词表里**只有 ≤6 个的模板**：8P（8 个）与服务业的六类模板这次不进，因为
  `MAX_FISHBONE_BONES = 6` 是契约硬上限，8P 要靠截断落地——那是改用户的模板，不是照它画；
- 这条路读的是 `topic`。外层 agent 把「按 5M1E 画」压缩掉之后就认不出来，那时退回
  模型自定。这是词面判据的天花板，不是实现疏漏。

## 6. `problem` 与类别：谁先定

**problem 先定，类别随它。** 理由：类别是"**这个问题**的成因面"，是关于 `problem`
的函数，不是关于主题的函数——同一个主题换个问法（"为什么转化率上不去" /
"为什么留存率上不去"）该长出不同的类别。先想类别再套问题，必然长出"这个主题分几块讲"。

提示词里的做法：`problem` 在 JSON 里排在前面（改之前就是这个顺序），再加一句
"**先写 problem，再定一级分支**……写完回头对一遍，每一个一级分支都要能填进
「（这个分支）出了偏差 → 主骨上那个为什么」，填不进去的换掉"。

**代码侧判不了"对不对得上"。** 那是语义判断，一个正则或词表只会给出一个看起来很客观
的错数。所以 `_fishbone_shape_diagnostics` 在开关打开时只做一件事：把
`FISHBONE_CATEGORIES_INCOMPLETE`（缺 5M1E 哪几类，warn）换成
`FISHBONE_CATEGORIES_UNFIXED`（这次是哪几个维度，info）——用户仍然要知道"这张图没走
5M1E"，只是它不再是缺陷。

## 7. 五个主题 × 开/关（真模型，`scripts/measure_fishbone_categories.py`）

模型 `deepseek-chat`，纯主题（无材料、外部检索关），每格一次。

| 主题 | 关：类别 | 关：硬塞 | 开：类别 | 开：硬塞 |
|---|---|---|---|---|
| ① 为什么团队协作效率低 | 人/机/料/法/环/测 | **5** | 职责/沟通/工具/流程/激励 | **1** |
| ② 为什么设备故障停机时间降不下来 | 人/机/料/法/环/测 | **1** | 技能/备件/点检/工具/环境 | **0** |
| ③ 为什么客户复购率上不去 | 人/机/料/法/环/测 | **5** | 体验/价值/触达/关系/竞品 | **0** |
| ④ 为什么报销审批要两周 | 人/机/料/法/环/测 | **4** | 层级/规则/系统/票据/排期 | **1** |
| ⑤ 为什么推荐算法准确率不达标 | 人/机/料/法/环/测 | **0** | 数据/特征/模型/评估/算力 | **0** |
| **合计** | | **15** | | **2** |

**"硬塞"的判据（可复核）**：把这条原因搬到另一个类别下读一遍，**是否更顺**。更顺就
算一次。逐条原文重跑一次即可拿到（`--free both --json scripts/_fishbone_categories.json`
的产物；`_` 前缀的文件不入库，与仓库里其它测量产物同一惯例）。

关组的硬塞都是同一个形状——**被 5M1E 逼着归类**：

- ① 「料」下：输入信息不完整 / 文档与知识沉淀差（信息与知识这一类在 5M1E 里没有位置）；
  「环」下：目标与优先级冲突（那是"信息/目标"，不是环境）。
- ③ 「料」下：产品同质化严重 / 产品迭代跟不上需求（那是市场与产品，不是"料"）；
  「人」下：客户画像不清（那是数据）。
- ④ 「机」下：系统流程设计冗长（那是"法"的流程）；「环」下：组织层级多、沟通环境不畅。

开组两次硬塞都是"相邻面"的边角：「职责」下写"能力与任务不匹配"（偏技能）、
「层级」下写"职责边界不清"（偏规则）。

**② 是对照组**：5M1E 本来就合适，关组只有 1 条硬塞，开组 0 条——而且类别被改写成了
「技能/备件/点检/工具/环境」，仍然是那五面，不是"话题分类"。这说明开关没有把好的情况
改坏。

### 新发现的两个问题（不在这次改动范围内，但必须记下来）

1. **① 开组有 5 条「改进动作」**：五根骨下面各挂一条，`CROSS_BRANCH_DUPLICATE` 报了。
   类别变抽象之后，模型更倾向用"改进动作"把格子填满。`_FISHBONE_BODY` 里已有"不要写
   建议"，但它在 system 里距离输出很远（本仓库已经三次记过这条教训）。**下一件事**：
   把"类别下面写的是原因，不是改进动作"这句话挪到 user 末尾再说一遍。
2. **⑤ 两组的"原因"都写成了名词短语**（"算法工程师能力""样本覆盖与规模"），不是
   "一句话说清什么导致了主骨上那个问题"。这个形态问题**与类别固不固定无关**，两组都有，
   这次改动既没治好也没加重它。

### 覆盖面实测

开组五次里有四次满足"至少三个成因面"（①②③④）。**⑤ 只覆盖两个面**（物+法：数据/特征/
算力 + 模型/评估），缺"人"与"境"。但 ⑤ 正是 5M1E 最不合适的主题——「算力」在 5M1E 里
完全没有位置（只能塞进「机」）。所以这一次"不满足四面临时约定"，换来的是一张**比六类更
贴题的图**。覆盖面约束是提示词层的约束力，不是硬保证；它挡住的是"五个类别都在同一面"，
挡不住"这个主题真的只有两个面"。

## 8. 一处自评：会不会退化成普通思维导图

**会退化，但退化的那一半本来就没在兑现。**

鱼骨图的形状（鱼头 + 主骨 + 骨 + 刺）与左右对称的排布都没有变，变的只是"骨有哪几根"。
真正被放弃的是"六个固定维度逼你想全面"——那条约束的价值建立在**六个维度对该主题都
成立**之上。对制造主题它成立（②：关组 1 条硬塞）；对协作、复购、审批它不成立
（①③④ 关组 13 条硬塞）。**一条逼着模型把原因塞进不属于它的维度的约束，买到的是
"看起来全面"，代价是"归类不可信"。**

买到的与失去的哪个大，取决于一个可量的东西：**硬塞条数**。这次 15 → 2；而"不全面"
没有对应的数字——关组那 15 条里，真正被想到的成因面并不比开组多，只是被摊到了六个
标签上（① 关组的"信息/知识"那一面就整个躲在「料」与「环」里，而开组有独立的
「沟通」与「工具」）。

第三条路已经落在提示词的第三层：**模型定类别，但必须覆盖四个成因面里的至少三个**
（第 4 节）。它比"固定六类"弱（不是硬保证），比"完全自由"强（模型不能只挑一个面）。
如果要更强的保证，正确的下一步不是把六类钉回去，而是在代码侧判覆盖——那需要给每条
原因判定"它属于哪一面"，也就是一次模型调用。这次没做，因为那会让每次鱼骨生成多付一次
调用，而它买到的东西（挡住"五个类别都在同一面"）实测 5/5 一次都没发生。

## 9. 这次没做

- **8P / 服务业模板进词表**：要动 `MAX_FISHBONE_BONES`（契约硬上限 6）。8P 画成 8 根骨
  是正确形态，但那是一次契约改动，与提示词不是一件事。
- **语义级的"硬塞"检测**：判不了就明说（第 6 节）。人工读 `scripts/` 的输出是目前唯一
  可靠的办法。
- **"改进动作"混进原因**：见第 7 节第 1 条，下一件事。
