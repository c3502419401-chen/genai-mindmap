# 用户路径测试：让"用户走不到"开始有红灯形态

这一轮只做一件事：**给"用户以为存在、界面上却没有"的那类缺口补上红灯**。它不修任何
产品代码——因为这一轮的产出要能回答一个反事实问题：如果早有这样的测试，那四个撞出来
的缺陷会不会被抓到。

答案在最后一节，而且不好看：**四个里只有一个**。前面几节说明为什么。

---

## 一、起点：3311 条用例没抓到的四种缺陷

写用户手册时撞出来的四条，全都不让任何用例变红：

```
① DELETE /api/mindmaps/{id} 实测 405      没有删除导图的接口
② 移除 / 删除 并排                        两个词像同一件事，后果差一个数量级
③ 拖到第 2 层节点下面失败                 684 种组合里 385 种报「算不出落点」
④ 手动节点无标记                          界面分不出"模型没找到依据"与"你自己加的"
```

它们的共同形状不是"代码算错了"，而是**代码在、用例绿、用户走不到**。既有 87 份 spec
测的都是"这个函数算得对不对"；没有一条从"界面上有一个按钮"这个前提出发。
前端也**没有 E2E 框架**（无 playwright / cypress / puppeteer），零条用例从"浏览器打开
页面"走到"拿到一张图"。

## 二、第一层：页面动作清单（本轮主体）

不引入任何新依赖，用现有的 vitest + jsdom。每个动作只断言两件事：

1. **有一个可点入口**——在 DOM 里，而且此刻真的可见；
2. **点了之后发生了什么**——发出了哪个请求，或改了哪个状态。

### 为什么"可见"是一个必须自己实现的判据

这个仓库的浮层几乎都是 `v-show` 常驻挂载（`HistoryDrawer`、材料面板、偏好浮层、
消息面板），理由是"收起只是看不见，DOM 与键盘顺序都还在"。代价是
`wrapper.find('[data-test="x"]')` **在收起状态下照样能找到**——只查 DOM 的判据会把
用户看不见的按钮算成入口，于是整份清单永远绿。

`tests/helpers/user-path.ts::visible()` 沿 `parentElement` 上溯看每一层的内联
`display`（`v-show=false` 写的就是 `display:none`，jsdom 不会替我们算继承）。
材料面板就是活例子：挂载后它在 DOM 里，`visible()` 说它不可见，点了「+」才可见。

### 清单的形状

清单是**数据**（`ActionPoint[]`），不是散落的用例：

```ts
{ name: '删除导图', where: '历史抽屉', locator: { selector: '[data-test="drawer-map-delete"]' } }
```

- 找不到入口，报错是这句话：`用户路径缺口：历史抽屉没有「删除导图」的可点入口（找不到
  选择器 …，或它此刻被 v-show 收起来了）`。缺口自己会说人话，不用读栈。
- 每个动作一行登记，`point(ACTIONS, '删除导图')` 按名字取——名字拼错当场红。
- 文件末尾有一条 meta 用例：**每条动作要么被本轮点到，要么登记了一处真实存在的手势
  覆盖**（`coveredBy` 指向的 spec 文件必须真的存在）。清单与用例各走各的，会在这里红。

### 覆盖：50 个动作 / 39 条用例

| 组 | 动作数 | 文件 |
| --- | --- | --- |
| 材料 | 10（添加 / 管理 / 粘贴正文 / 添加文本 / 上传文档 / 上传图片 / 录音 / 移除 / 清空来源 / 彻底删除） | `tests/user-path-input.spec.ts` |
| 生成 | 7（输入主题 / 选拆解方式 / 选图型 / 发送 / 取消 / 深度思考 / 智能搜索） | 同上 |
| 导图 | 7（☰ / 保存 / 新建 / 打开 / 打开列表弹窗 / 删除导图 / 删除导图·弹窗） | 同上 |
| 画布 | 10（改朝向 / 改文字 / 加子节点 / 加兄弟 / 删除节点 / 展开 / 收起 / 展开整支 / 拖动* / 双击空白*） | `tests/user-path-workspace.spec.ts` |
| 引用 | 3（看引用清单 / 看上下文 / 跳原文） | 同上 |
| 知识库 | 5（列表 / 删除材料 / 别名清单 / 删除别名 / 找出可合并的） | 同上 |
| 检查 | 3（检查结构 / 一键修复 / 应用建议） | 同上 |
| 导出与导入 | 5（四种格式 / 导入） | 同上 |

\* 拖动与双击空白是**手势**，界面上没有可点的东西。它们不进 `entryOf`，而是用
`coveredBy` 登记覆盖文件（`node-drag.spec.ts` / `canvas-keys.spec.ts`），由 meta 用例
核对文件存在。这样"已覆盖"这句话是可查的，不是一句注释。

### 结果：39 条全绿，但这不等于"没问题"

那四个缺陷**在 HEAD 上已经修掉了**（`9e6a675` 加删除导图、`2c3ade4` 拆开移除/删除），
所以这一轮结束时清单是绿的。绿本身没有信息量——有信息量的是**它会红**。两处反向验证
（只临时替换产品文件，跑完立刻还原，`git status` 干净）：

| 临时回退 | 结果 |
| --- | --- |
| `SourceInputs.vue` → `2c3ade4^`（按钮文案回到「移除」） | 2 条红：`材料面板没有「移除」的可点入口`、`没有「彻底删除」的可点入口` |
| `HistoryDrawer.vue` → `9e6a675^`（抽屉里没有删除导图） | 1 条红：`历史抽屉没有「删除导图」的可点入口` |

复现方法写在第八节。

### 过程中撞到的三件事（本轮不修，记下来）

1. **两个同名「删除」并排在同一屏**：左抽屉开着时，导图列表行有「删除」；知识库抽屉
   叠上来之后，材料行也有「删除」，别名行还有第三个。三处都没有 `data-test` 也没有
   `aria-label`，只能靠"在 `aside[role="dialog"]` 里按文档顺序取"来区分。这是缺陷②
   的同族现象——**它还在**，只是这一次它不是撞出来的那个词对。
2. **「管理材料」只在有材料时才存在**：它挂在材料缩略图那一行里，而那一行
   `v-if="sources.items.length"`。所以一份材料都没有的新用户看到的入口只有「+」
   （`pickFiles`：打开面板 + 弹系统文件框）。行为是对的，但"管理材料"这个词在空状态下
   不存在，清单里必须按条件写。
3. **「检查结构」打的是 `/optimization/suggest`**，不是 `/optimization/check`：手动路径
   要连"建议"与"补关系"一起拿回来（`stores/structure.ts::runFull`），`check` 只服务
   生成之后那次免费体检。术语与端点错位，无害，但读代码的人第一眼会以为按钮名对不上
   端点名。

## 三、第二层：前端版 `find_unwired`

后端有 `backend/scripts/acc3/find_unwired.py --gate`，前端没有对应的东西。这一层把它补上：
`frontend/scripts/find_unwired.mjs`。

**它抓的是这一类**：后端加了路由、`client.ts` 加了函数、但没有任何界面调用它——那正是
"实体消解没有产生入口"的形状，也是「删除导图」曾经的样子。

### 判据

照后端 v2 的精神，数**语法树里的引用节点**而不是文本里的字面出现：这个仓库的注释极爱
写函数名（"见 `deleteMindMap` 的 docstring"），按 `\bname\b` 数文本会把**只在注释里被
提到**的函数算成"有引用"，于是清单只会变短而没人发现。

- 候选：`src/api/client.ts` 里 `export function` / `export async function`（44 个）；
- 引用：`src/**` 全部 `.ts` 与 `.vue` 的 `<script>` 段（`ts.createSourceFile`），
  排除 `api/client.ts` 与 `api/schema.d.ts` 自己；
- `.vue` 的 `<template>` 段只做窄匹配（`@事件="fn(`、`:prop="fn"`、`{{ fn( }}`）——
  模板里出现函数名基本就是接线；
- 另记一列 `tests=`：**只在用例里被用到、产品代码零引用**，是最可疑的一档。

### 结果：44 个导出函数，1 条零引用（第 3 件已销账三条）

下面这张表是当时的快照。**账本那三条已经接上界面了**（`stores/ledger.ts` +
`components/EditLedger.vue`，判据与折叠口径见 `EDIT-LOG.md` 七·五），基线里那三条已
删除，闸门现在只剩 `changePassword` 一条——所以表里保留原判定，好看出"该接"与"已接"
之间差的是什么：不是决定，只是没人做。

| 函数 | tests= | 判定 |
| --- | --- | --- |
| `getEditSummary` | 0 | **已接**（第 3 件）：账本标题行那句摘要 + 三条读数就是它。原判「该接」——后端 `GET /mindmaps/{id}/edits/summary` 在、`client.ts` 的函数在、界面零入口；`client.ts` 自己的注释说它是"这一版真正的交付物"。 |
| `listEditEvents` | 0 | **已接**（第 3 件）：同一个面板的列表，逐条念成人话。原判「该接」——summary 给分布，它给"那 42 条具体是什么"。 |
| `getEditHealth` | 0 | **已接，但只在异常时露面**（第 3 件）：`chain_suspect` 为真才显示一行琥珀。原判「该接，但接在哪还没定」——它是**运维视角**，判到最后是"接在同一块面板里、正常时一个字都不显示"，而不是另开一个管理视图。 |
| `changePassword` | 0 | **不该接（有意）**。理由已经写在界面上：`AuthPanel.vue` 已登录那段明写"不再给一个改密码的入口……那是设置页的事"。这一版没有账号设置页，所以入口缺席是决定不是遗漏。等设置页上线，它会变成第一条"该接"。 |

现在基线里只剩一条 `intentional`（`changePassword`）——那三条 `gap` 随第 3 件一起
从基线里删掉了。每条都写了 `reason` 与 `evidence`。闸门是**棘轮**，不是"零"：

```
node scripts/find_unwired.mjs           # 汇总 + 清单
node scripts/find_unwired.mjs --suspects # 只列零引用
node scripts/find_unwired.mjs --gate     # 退出码非 0 = 有基线之外的新增
```

两条反向检查让基线不腐烂：条目已经不再零引用 → 打印提示（不红，该删掉这一条）；
条目声明的 `evidence` 文件不存在 → **红**（豁免的理由被删了而豁免还在）。

### 它漏什么（当闸门用之前必须承认的）

- 动态取值（`client[name]`、注册表）会误报成零引用；
- 只被模板里事件名字符串调用的不算（那本来也不是 `client.ts` 的函数）；
- `.vue` 的 `<script>` 段按最外层一对标签切，模板里出现 `"<script>"` 字面量会切错
  ——真出现时脚本打印该文件并跳过，不静默当零引用。

## 四、第三层：真浏览器三条主路径 —— **本轮不做**

要做的形态是：① 生成 → 保存 → 删除 ② 无材料生成（纯主题）③ 导入 → 导出往返。

**不做的理由**，按重要性：

1. **它唯一独有的是"真 HTTP 状态码"，而这一条有更便宜的抓法。** 第一层把 `fetch` 换成
   替身，所以 405 永远看不见（详见第五节 ①）。要抓它，最便宜的是后端契约测试里补一条
   `DELETE /api/mindmaps/{id}`（`backend/tests/test_one_path.py` 走 TestClient → 真路由表
   → 405 会红），成本是一段二十行的用例，而不是一个 devDependency + 配置 + CI 步骤。
2. **②③ 两条在第二层已有覆盖**：导入导出四种格式全部断言了"选了就发出
   `POST /export/{format}`"、"选中文件就发出 `POST /mindmaps/import`"；无材料生成断言了
   纯主题就能发 `POST /agent/runs/stream`。真浏览器再加一遍，多出来的是**渲染**，而渲染
   失败的形态是"页面白"，`smoke-canvas.spec.ts` 已经在 jsdom 里挡了一部分。
3. **成本落在"后端"而不是"浏览器"上**：真后端 7000 多行、模型调用几十秒。要么用替身
   后端（那就不是"真浏览器真后端"，价值掉一半），要么只跑不依赖模型的路径（那正好是最
   不需要它的第③条）。

**如果下一轮要做，形态已经清楚**：

- `playwright` 一个 devDependency + `frontend/playwright.config.ts` + CI 里一步；
- **跑在本地手动 + CI 的 nightly**，不进 required check：它要连后端，而后端在 CI 里
  要么是 docker-compose 起一个（成本在本轮之外），要么是替身；
- 只跑路径②③（无模型），① 单独一条用**替身后端**（一个 200 行的 FastAPI 假实现，
  照 `client.ts` 里那 44 个函数用到的端点写），因为 ① 的价值在"删除"这一下，而那一下
  不需要模型。

## 五、自评：四个缺陷，这一轮抓到几个

**一个。** 逐个说，包括为什么抓不到——这个答案比测试本身重要。

### ① 没有删除导图的接口（`DELETE /api/mindmaps/{id}` → 405）：**抓不到**

第一层把 `fetch` 换成替身，`deleteMindMap()` 发出去的是一个"看起来对"的请求，替身一律
回 200/204。**405 是后端路由表的事实，只在 HTTP 这一层存在**，而这一层的判据是
"界面上有没有一个能点的删除按钮、点了有没有发出 DELETE"——两条当时都会绿（按钮在、
请求也发了），红不了。

这不是"测试不够多"，是**判据所在的层不对**。抓它只有两条路：后端契约测试（最便宜）
或第三层（真浏览器 + 真后端）。这也是为什么第三层的判定不是"贵所以不做"，而是
"它唯一独有的事，有更便宜的抓法"。

### ② 移除 / 删除并排：**抓到了**（已用反向验证证明）

回退到 `2c3ade4^` 的 `SourceInputs.vue`，两条用例立刻红，报的正是缺口本身：
`用户路径缺口：材料面板没有「移除」的可点入口（找不到 aria-label 以「从本轮移除」开头）`。

但要说清它抓到的是什么：**它抓到的是"某个词的入口是否还在"，不是"用户会不会混淆"。**
混淆是人的判断，红灯只能锚在一个可核对的事实上（这里是按钮的文案/aria-label）。
所以它防的是"文案被改回去或被删掉"，防不了"再想出一个同样混淆的新文案"——那仍然要
靠人读一遍。

### ③ 拖动预算截断（684 种组合里 385 种算不出落点）：**抓不到**

需要**真数据**：一棵超过 `visibleNodeLimit` 的树 + 真实的落点几何。第一层只看入口，
"拖到第 2 层节点下面"没有按钮可点（它是手势，`coveredBy` 指向 `node-drag.spec.ts`）。

而它**现在已经被覆盖**了——`node-drag.spec.ts` 里有 136 节点 + 预算 20/3 的用例，
`renderSource.root` 是截断后那棵树。所以这一条的状态是"有覆盖，但不是本轮这一层给的"。
上一轮定性里说的"42 条 previewMove 全在一棵 6 节点的树上、预算截断从未被执行"已经不成立。

### ④ 手动节点无标记：**抓不到，而且这类缺口本来就没有红灯形态**

因为**契约里根本没有这个信息**：`MindNodeData` 没有"这个节点是手动的还是生成的"字段，
`MindNode` 的契约里也没有。测试无法断言一个不存在的信息——写 `expect(node.dataset.origin)`
只会测出 `undefined`，而 `undefined` 与"模型没找到依据"在界面上长得一模一样。

这条缺口要变红，只能先有一个产品决定：给节点补一个 `origin: 'user' | 'agent'`（或等价
的东西，比如"手动添加"的视觉标记）。目前产品选择的是**把它写成边界**——`App.vue` 的
文案里明写"或者是你自己加的"，`MindNode` 不装作知道。

所以第四类的正解不是补测试，是补**字段**；测试永远等在产品后面。

### 这一节的结论

| 缺陷 | 本轮抓到 | 为什么 |
| --- | --- | --- |
| ① 删导图 405 | 否 | 判据在 HTTP 层，不在 DOM 层 → 该补后端契约测试 |
| ② 移除/删除并排 | **是** | 文案是 DOM 事实，可核对（已反向验证） |
| ③ 拖动预算截断 | 否 | 需要真树 + 真几何 → 已有 `node-drag.spec.ts` 覆盖 |
| ④ 手动节点无标记 | 否 | 契约里没有这个字段 → 缺的是产品决定，不是测试 |

下一轮该往哪补，从上表直接读出来：**先补 ① 的后端契约测试（最便宜、最该先做）**，
再判 ④ 要不要补字段；③ 已经有人管了。

## 七、跑法与维护

```bash
cd frontend
npm test -- --run                      # 全量（含两份用户路径）
npm run type-check
npx vitest run tests/user-path-input.spec.ts tests/user-path-workspace.spec.ts
node scripts/find_unwired.mjs --gate   # 前端版闸门
```

**加一条动作时**：在对应 spec 的 `ACTIONS` 里加一行（`name` / `where` / `locator`），
写一条用例 `tap()` 或 `entryOf()` 它。忘了写用例，文件末尾的 meta 用例会红。

**删一条动作时**：把清单那一行删掉。只删代码不删清单，meta 用例同样会红——这正是
它存在的理由（清单比产品代码更难被注意到）。

**新增零引用 client 函数时**：`--gate` 会红。要么接到界面上，要么在
`scripts/unwired_baseline.json` 里写清为什么它可以零引用（并给 `evidence`）。

**做反向验证时**（确认清单真的会红）：
