# 压链拼标题的准入条件：「放得下」不是「读得懂」

2026-11-27。改的是 `optimization/repair.py::_joined_label` 的第二档。这一篇记
**判据为什么是这个方向**、**在 20 棵验收树上量到什么**、以及**这条规则还剩哪些已知
的失手**。

---

## 一、病灶：第二档只有一个条件，而它是长度

压链（`_absorb`）要把两层的标题放到一个节点上，三档：

| 档 | 改前判据 | 结果 |
|---|---|---|
| 一 | 词面包含 | 取长的那个（「监督学习」/「有监督学习」） |
| 二 | **`len(拼接) <= 24`** | 拼接 |
| 三 | 再长 | 取内层 + 外层标题写进 `detail` 第一行（`原上级：…`） |

第三档本来是对的（不丢内容，`test_collapse_never_loses_the_outer_title` 钉着）。
坏在第二档：**"两行放得下"被当成了"读得懂"**。于是「经典篇目背诵 20% / 背诵成绩
占比两成」（21 字，放得下）——同一句话的两种说法——被拼成一句，读起来是重复。

验收报告 §6.4 第 3 条把它点名为"可读"这一维扣分的**单一系统性成因**：只有长度一个
条件时，**任何**放得下的父子标题都会被拼上，包括复述。

## 二、先给 75 个 ` / ` 分了来源（这一步不能省）

`data/acc_trees/` 是「生成（模型）+ 收尾修复（`MINDMAP_AUTO_REPAIR`）」之后的产物，
光看 label 分不清 ` / ` 是模型写的还是压链拼的，而能改的只有后者。

判据：**`id` 跳代**。生成侧的 id 严格按当时那一层编号，压链**保留内层 id、吃掉
一层**——所以压链产物的 `id` 段数会比它当前所在的位置深一层。

```
1130 个节点：seg == depth-1（正常编号）976，seg == depth（跳代）110
             110 里有 20 个是 root（它本来就没有父层），真跳代 90
90 次压链的分解：第二档拼接 74（含 " / "）+ 第三档降级 11（detail 带「原上级：」）
                 + 一档取长的 5
```

75 个含 ` / ` 的节点里，**74 个是压链产物**，1 个是模型自己写的并列
（`S12/s2-3` 的「导出 PNG / PDF / W」——生成侧 16 字硬切的产物，改判据也不会让它
消失）（`scripts/_probe_slash_labels.py`）。

**顺带一个方法论上的坑**：第一版探针把判据写成 `seg > depth`（少减了 1，因为 id
不数 root），跑出来"75 个里 0 个是压链产物"——一个把结论完全颠倒的假阴性。是
`acc_trees` 与 `acc_trees-before-fix` 两轮产物的对照（后者也有同样的 ` / `）把它
顶回来的。**判据写错一格，结论就反了**，这类探针必须用一个独立的第二来源校验。

## 三、判据方向：黑名单（拦复述），不是白名单（限定类别）

上一轮给的方案是白名单：**只有 left 是 right 的上位词/标题名、或 right 是 left 的
量化补充时才拼，其余走第三档**。照着写之前，先把 74 对逐对读一遍
（`scripts/_probe_join_rule.py` 有全部明细），分布是这样的：

| 类型 | 数量 | 例子 |
|---|---|---|
| 维度名 + 它的取值（**互补**） | 约 54 | `服务器费用 / 300 元/月`、`数据库选型 / 使用 PostgreSQL`、`第 1 月里程碑 / 体测与计划生成 MVP` |
| 同一件事的两种说法（**复述**） | 约 20 | `经典篇目背诵 20% / 背诵成绩占比两成`、`评审对象为导图编辑器 / 新版导图编辑器` |

「维度名 + 取值」占 3/4，而它们**不是**上位词、也不是量化补充（`第 1 月里程碑` /
`体测与计划生成 MVP` 既不包含也不含数字）。白名单会把这一批 54 条全部赶进第三档
——那是拿"外层标题从画布上消失"换"没有病句"，等于换个方式不可读。

所以判据反过来写：**只拦"两段在说同一件事"**。可算的近似是**两段共享的连续汉字**：

```python
shared = _shared_han_run(left, right)      # 最长公共连续汉字子串
if len(shared) > JOIN_MAX_SHARED_CHARS:    # > 1
    return right, True                     # 判为复述 → 第三档
```

为什么是 2 个汉字：一个字不说明任何事（「第一层 / 第二层」共用「第」），两个字就已经
是一个主题词（「背诵」「学时」「确认」「培训」）——**复述必有共同主题词**（讲的是
同一个对象），**互补则各在各的域里**（维度名 vs 取值）。

标点、数字、拉丁字母不参与：`20%` 与「两成」是同一个数的两种写法，那要靠数字判据才
认得出，不在这一条里做（见 §五的漏网）。

**零网络调用**：`repair()` 的契约是一次模型调用都没有（模块 docstring 第 86 行），
而压链跑在每一张图的收尾，还要在修复记录里给出可复述的理由。词面判据给了那个理由。

## 四、量到了什么

`scripts/_probe_replay_collapse.py`：把 74 个压链产物**逆向还原成压链前的一层两
节点**（含 ` / ` 的必然是第二档产物，label 可无损拆回两段），再跑一遍当前 `repair()`。

```
磁盘上的树（压链后）：节点 1130，含 " / " 75，原上级 11
逆向还原成压链前   ：节点 1204（+74 = 每条压链补回一个外层）
跑完当前 repair    ：节点 1130，含 " / " 45，原上级 41
节点数是否回到原样：是          ← 没有出现额外的同级合并
二次 repair 是否幂等：是
```

| | 改前 | 改后 |
|---|---|---|
| 含 ` / `（压链产物） | 74 | **44**（另 1 条是模型写的，不变） |
| 外层标题降级进 `detail` | 11 | **41** |
| 节点数 / 幂等 | 1130 / 是 | 1130 / 是 |

降级的 30 条里，`label` 全部是可独立读懂的短语，没有一条变成半句或空标签
（逐条见 `python scripts/_probe_replay_collapse.py --detail`）。按域看，全部 7 条
"费用/指标 + 数字"（S15）与全部 3 条"第 N 月里程碑"（S18）都**保留拼接**——这正是
白名单会误杀、黑名单不会碰的那一批。

## 五、已知失手（两条，都留着）

**漏放 1 条**：`三项合计百分制 / 20+30+50 构成总分`（S06/b4-4-1）。left 没有阿拉伯
数字、两段汉字只共享「分」——数字判据和共享判据都抓不到。要抓它得写"left 含'合计/
总计'且 right 含数字"这类规则，那是为一棵树的一个节点过拟合，不做。

**误杀 11 条**，全部是"共享词是主题词、但 right 有 left 没有的新信息"：
`课程性质与学分 / 32 学时 2 学分`、`需求与原型确认 / 11/30 完成确认`、`调度方式 /
调度员手工排线`、`培训与准入 / 培训课程与考试` 等。它们的第三档产物反而更短更好读
（`32 学时 2 学分`、`11/30 完成确认`、`调度员手工排线`、`培训课程与考试`），代价
是类别/维度那层意思挪进了 `detail`。按"两害相权"（见下）接受。

**一处与上一轮报告的分歧，需要摆出来**：报告把
`文体演变主线目标 / 把握各体文学演进脉络`（S06/b2-1-1）和
`经典篇目背诵 20% / 背诵成绩占比两成`（S06/b4-1-1）并列点名，但这两条不是同一类：

- `b4-1-1` 是**复述**——"背诵占 20%"与"占比两成"是同一个数的两种写法。判据拦它。
- `b2-1-1` 是**维度名 + 它的取值**——"主线目标"是一个维度，"把握各体文学演进脉络"
  是这个维度的内容，拼起来读作"A 下的 B"。**判据不拦它**，它和 S15/S16 那 54 条
  同一类。

如果按报告的口径把它也算坏，那"维度 + 内容"这一整类都得算坏，于是 54 条要一起进第
三档——那就回到了 §三否掉的白名单方案。**所以这是"该拼"标准的边界，不是判据的
bug**：标准是"拼起来读作一个层级关系还是两句话堆叠"，按这个标准 `b2-1-1` 通过。
要是 YG 认为 `b2-1-1` 也读不通，需要改的是标准本身（那是一条产品判断），先别改判据。

**一个没预料到的形状**：如果两条分支各只有一个孩子、两个孩子同名（`监督学习 →
迁移学习` / `无监督学习 → 迁移学习`），降级后两个节点都只剩「迁移学习」→ 同层同名
→ 被 `DUPLICATE_LABEL` 合并成一条。两个外层标题都还在（各降级成 `detail` 的第一行），
但**画布上看不出它们原本分属哪条分支**。这个形状在 20 棵验收树里一次都没出现
（重放节点数 1204 → 1130 不变 = 没有额外的同级合并），用例
`test_cross_branch_duplicates_are_judged_before_the_repair` 把它钉住。

## 六、自评：「取内层 + 外层进 detail」会不会太多

上一轮担心的是"75 个里 60 个走第三档，大量外层标题从画布上消失"。实测是
**30/74 = 41%**，不是 80%。

**判断：这是净改善，不是把一件事修成另一件事。** 三条理由，按强度排：

1. **降级不丢内容，拼接丢可读**。第三档把外层那句放进 `detail` 第一行（悬停卡片
   `displayBody` 优先取 detail），用户想读时读得到；而拼错的代价是**每次扫图都读到
   一句病句**，且没有任何地方能退回正确的那句。两种损失不对称。
2. **降级后的 label 是完整短语，不是残句**。30 条逐条看过：`靠 Excel 加微信群预约`、
   `未通过培训不得预约高风险设备`、`设置每人容量与方向配额`——它们本身就是这一支
   讲什么。失去的是"调度方式"这类**维度名**，而维度名在父层通常已有上下文
   （`s19/s1` 下面是「现有预约方式」「调度方式」这类同级兄弟，相邻节点头上就有）。
3. **判"该拼"的标准是可算的，而且它判对了 62/74**。标准写成一句话：
   **拼起来的 label 要读作一个层级关系（A 下的 B），而不是两句话的堆叠；可算的近似
   是两段无共享主题词。** 按这个标准，那 54 条"维度 + 取值"该拼（不共享主题词），
   那 20 条复述不该拼（共享主题词）——判据在 74 条上一共错了 12 条，其中 11 条错的
   方向是"本该拼的降级了"（两害里轻的那一害），只有 1 条是"复述还拼着"。

**唯一需要盯的指标**：降级率。改后第三档占 41/90 ≈ 46%（其中 11 个是"本来就拼不下"、
30 个是新增的判复述；新增的那部分是 30/74 = 41%）。如果后续轮次这个数继续涨（比如
过 60%），说明判据在过度拦，那时该回头收紧共享词判据（例如要求共享词落在两段的
**同侧**，而不是任意位置），而不是加白名单。

## 七、可复现

```
python scripts/_probe_slash_labels.py                 # 75 条逐条：拆成 left / right
python scripts/_probe_join_rule.py                    # 74 对：判据 vs 人工 ground truth
python scripts/_probe_replay_collapse.py              # 核心数：75 → 45、11 → 41、幂等
python scripts/_probe_replay_collapse.py --detail     # 逐条：改后是拼还是降级
python -m pytest tests/test_optimization_repair.py tests/test_generate_auto_repair.py -q
```

`scripts/_structure_audit.py` 的 **F 判据对这次改动不敏感**：F 只量 `label <= 24`
的上限，而改动只会让 label 变短。改前改后都是 20/20 过、超长 0——所以"F 通过"不能
当作这次改动有效的证据，能当证据的是 §四那张表的 75 → 45。
