# 用户手册：从装好到做出一张有用的图

这份文档写给**第一次用这个产品的人**，不写给评审、也不写给下一个改代码的人。
每一节都按"照着做"来写：先说要先有什么，再写你点哪里，再写**点完之后屏幕上会发生什么**。

> **本文的实测环境**（2026-11-26）：后端 `8000` 走 `run-backend.bat`（带模型密钥），
> 前端 `http://localhost:5173`，浏览器 1600×900，游客身份（`GET /api/auth/me` 拿 cookie，
> 游客配额未启用）。文中"实测"两个字的数字都是这一次点出来的；其他数字注明出处。
>
> **截图**都在 `images/`。截的是真界面，不是示意图；图里的材料是一份 1029 字的
> 《校园垃圾分类推行方案》，能复现的步骤见文末附录。

---

## 一、这是什么

1. 你把**一份材料**（或只写一个主题）交给它，它生成一张**可编辑的导图**：思维导图 / 流程图 / 鱼骨图三种之一，每个节点尽量挂一条"这句话出自材料哪一段"的引用，**点一下能看到原文那一段**。
2. 它是**单机原型**：一个后端进程 + 一个前端页面，数据落在本机 SQLite（`backend/data/mindmaps.db`），没有多用户协作、没有权限隔离、没有云端同步。
3. 它**不做**这些事：不做翻译、不做知识图谱、不做实时协作；引用只保证"这句原文确实存在"，**不保证**"这个结论正确"（这一点在第 8 节 ① 说透）。

## 二、第一次上手

**【前提】** 后端与前端都已经起来（怎么起见 `START_HERE.md`）；浏览器能打开 `http://localhost:5173`。

一共 9 步。第 5 步之后要等半分钟到一分钟，其余每一步都是几秒钟的事。

### 第 1 步：打开页面

**你会看到**：上面一条窄顶栏（`☰` / 图名 / ⚙ / `+`），中间是一大块空白画布，写着
「还没有导图：在下方对话框写一个主题，或点「+」添加材料。」，最下面是对话框
（「主题或要求」输入框 + `↑` 生成按钮 + 「深度思考」「智能搜索」「添加材料 +」「🎤」）。

左上角是四个朝向按钮（向右 / 向左 / 向下 / 双向）和「撤销 / 重做」——还没有图，它们是灰的。

### 第 2 步：给材料（三种任选）

- **传文件**：点对话框里的 `+`。会直接弹出系统的文件选择框。可多选。
- **粘贴正文**：把**超过 120 字**的正文直接粘到「主题或要求」框里。它会自动变成一份材料，输入框里会留一句提示：「这段正文（N 字）已经放进材料，主题框里说要它做什么。」
- **在材料面板里粘**：点材料缩略区右侧的「管理材料」→ 面板里有「粘贴材料正文」→「添加文本到来源」。

**你会看到**：对话框上方多出一个材料缩略块，先显示「正在解析…」，解析完变成
「文档 · 1029 字」；材料面板里那一行变成「已就绪 · 1029 字」，并在下面多一行
「已在知识库　彻底删除」，列表上方另有一行小字把两个动作分开写：
「「从本轮移除」= 这次生成不用它，材料还在知识库里；「彻底删除」= 从知识库永久删除，不可恢复。」
（这两个词在 2026-11-26 改过，原来叫「移除」/「删除」，见第 8 节 ④。）

> 截图：`images/01-start.png`

### 第 3 步：写主题（可以不写）

在「主题或要求」里写一句话，比如「校园垃圾分类推行方案」。

**不写会怎样**：用材料标题当中心主题。实测输入框下面会直接说明：
「没写主题：用材料标题「campus-garbage-sorting」当中心主题。」

⚠️ 材料标题来自**文件名**。文件名不像标题时（`未命名.pdf`、`IMG_001.png`、纯数字），
它会拒绝拿它当主题，并让你补一句——所以**自己写一句主题最省事**。

### 第 4 步：选图型（默认"自动判断"）

对话框里那个折叠项叫「拆解方式与图型」，里面是两组：

- 拆解方式：通用 / 第一性原理 / 费曼 / 5W1H / 批判性
- 图型：自动判断 / 思维导图 / 流程图 / 鱼骨图

两组默认都是「自动判断」。不知道该选什么就都留着默认（第三节讲差别）。

### 第 5 步：点 `↑`「生成导图」

**你会看到**（按时间顺序）：

1. **立刻**（实测 < 0.15 秒）界面就有反应：对话框收成一条进度，右上出现「取消」。
2. 几秒后画布开始长：中心主题先出现，然后一级分支、子节点一个个冒出来。
   进度行写「正在生成 · 已写完 7/7 章的子树 · 8 秒」这样的字样。
3. 等待期间**画布上的节点会重排**（布局是自动算的），这是正常的。

**要等多久**：本次实测 1029 字材料 → 64 节点，从点按钮到落地约 30–40 秒。
仓库里 20 条中文真实材料的实测是：首帧 P50 **0.09 秒**（P95 0.12）、中心主题上屏
P50 **5.4 秒**（P95 9.5）、完整树落地 P50 **31.3 秒**（P95 41.4，55–85 节点规模）——
出处 `docs/ACCEPTANCE-METRICS.md` §4.2。为什么会慢、怎么变快见第 8 节 ②。

> 截图：`images/02-generating.png`

### 第 6 步：落地

**你会看到**：底部状态行变绿，写「已落到画布（64 个节点） · 有 20 条诊断 · 还没保存」，
右边两个按钮「回到生成之前」「20 条诊断」。同时对话框从「生成导图」变成
「改这张图」（选中一个节点后是「改这个节点」）。

⚠️ **这一步的图还没存**。关掉页面就没了，见第 7 节。

> 截图：`images/03-landed.png`

### 第 7 步：看懂画布

**你会看到**：

- 右上角「显示 40 / 64 个节点」——这一屏只画了 40 个，数据里是 64 个（第 5.3 节）。
- 每个节点**右上角的小数字**（如 `1` `2`）= 这个节点有几条原文引用。鼠标悬停会显示「1 处来源引用（点击查看）」。
- 节点右下角的 `+N` = 这个节点还有几个子节点没画出来；`−` = 这个节点的子节点正显示着。
- 右上「适应宽度 / 全图」两档视图。默认是「适应宽度」；点「全图」会把整张图缩进一屏，
  64 个节点时字会小到看不清（实测如此，这不是坏了）。

> 截图：`images/04-fit-all.png`

### 第 8 步：点开一条引用（这是这个产品最该先学会的动作）

1. **点节点**：右侧滑出「节点详情与本次改动」。截图 `images/05-node-selected.png`
2. **点节点右上角的引用角标**（比点节点更直接）：抽屉里出现「来源引用（2）」，
   每条写着「文档 · campus-garbage-sorting.md · 第 423–432 字」+ 那段引文。
   截图 `images/06-refs-in-detail.png`
3. **点其中一条**：右侧换成原文抽屉，最上面是逐字引文「三期把清运改为分线路」，
   副标题「第 423–432 字 · 共 1,029 字」。截图 `images/07-quote.png`
4. **点「看上下文」**：抽屉里铺开原文，命中那一段用黄色高亮标出来，前后各 600 字。
   截图 `images/08-context-highlight.png`

如果这个节点**没有**引用，抽屉里会写「这个节点没有原文引用。」，紧跟一句
「这张图 64 个节点里有 47 个带原文引用（73%）。没有引用的节点不代表内容有错：……」
（第 8 节 ①）。

> 截图：`images/09-no-ref.png`

### 第 9 步：保存

顶栏没有保存按钮，保存有两个入口：

- `Ctrl+S`
- `☰` → 左侧抽屉「操作」区 → 「保存」

**你会看到**：状态行「已保存，版本 1。」，抽屉里状态行变成「已保存」。
`☰` 抽屉长什么样见 `images/10-menu.png`。

## 三、三种图型怎么选

**【前提】** 已经知道要处理的是什么材料（或什么主题）。图型在生成前选，生成之后要换图型只能重新生成。

| 图型 | 什么时候用它 | 画出来什么样 | 真实例子（仓库里已存的图） |
|---|---|---|---|
| **思维导图**（树） | 内容是**层级与归属**：一个主题分成几块，每块再分 | 中心主题在左，一级分支撑开，层层向右 | 「校园垃圾分类推行方案」：为什么要做 / 分类标准 / 设施改造 / 人员与责任 / 激励与约束 / 时间表与风险 / 验收指标（本次实测 64 节点） |
| **流程图** | 内容有**先后顺序**和**判定分支**：「先做什么，满足条件再做什么」 | 阶段竖排，判定节点是**菱形**，出口边写着「是 / 否」 | 「报销审批流程」：提交申请 → 形式审查 → 材料齐全吗？（是→转交财务 / 否→补齐材料）→ 金额超标吗？→ 付款 |
| **鱼骨图** | 内容是**一个结果的多种成因**：「为什么 X」，原因分属几大类 | 鱼头是那句「为什么」，主骨横贯，六根骨各带一串原因 | 「鱼骨基线」：为什么报销要 11 天 / 人（审批人休假）· 机（系统卡顿）· 料（票据缺失）· 法（流程层级多）· 环（跨部门协作）· 测（无时限考核） |

> 流程图截图：`images/11-flow.png`　鱼骨图截图：`images/12-fishbone.png`

**判断口诀**：能在脑子里画成"一条线往前走"的 → 流程图；能问"为什么"并列出几类原因的
→ 鱼骨图；剩下的（分类、清单、方案、笔记）→ 思维导图。

**三种图的编辑能力不一样，选之前要知道**：

| | 树 | 流程图 | 鱼骨图 |
|---|---|---|---|
| 视图收起（40 上限 / `+N`） | 有 | **没有** | **没有** |
| 拖动改结构 | 全部方向 | 只能**同一阶段内**换位次 / 换父步骤 | 只能**同一根骨上**换 |
| 跨阶段 / 跨骨拖动 | — | 拒绝 | 拒绝 |
| 阶段次序、骨的次序 | — | 拖不动（那是流程语义，不是排版） | 拖不动 |

**鱼的六个类别默认是固定的**：人 / 机 / 料 / 法 / 环 / 测（制造业 5M1E）。对着
「为什么团队协作效率低」这类主题，模型会被迫把原因硬塞进这六格（仓库
`docs/FISHBONE-CATEGORIES.md` §1 记录了实证：「料」下面写了「员工技能不足」）。
让类别随主题自由定要靠开关 `MINDMAP_FISHBONE_FREE_CATEGORIES=1`，**默认关**。

## 四、材料怎么给

**【前提】** 材料要在**点生成之前**加好；生成中材料面板是冻结的。

| 材料类型 | 怎么给 | 上限 | 代价 / 限制 |
|---|---|---|---|
| **文本** | 粘进「主题或要求」（>120 字自动转材料），或材料面板「粘贴材料正文」→「添加文本到来源」 | 合并后 ≤ 300000 字 | 最便宜；**<300 字的材料不当作语料**，会被当成"主题提示"（见下） |
| **文档** | 点 `+` 选文件：PDF / Word / PPT / Excel / HTML / Markdown / AsciiDoc | 每份 10MB；PDF 最多识别 20 页 | 解析要时间（PDF 逐页识别约每页 5–10 秒）；扫描件、图片型 PDF 要视觉模型（`MINDMAP_LLM_MODE=model`），demo 模式下会 422 |
| **图片** | 点 `+` 选 png / jpg / webp / gif / bmp | 每份 10MB | 同样要视觉模型；手绘草图、截图、白板照片都能读 |
| **语音** | 点 `🎤`（页面内录音），或 `+` 选 `.wav` | 每份 20MB | **只收 WAV，且采样率必须是 8000 或 16000**；服务端要配阿里云百炼凭证 `DASHSCOPE_API_KEY`，没配时上传 wav 直接 422。详见第 8 节 ③ |
| **主题（不传材料）** | 只在「主题或要求」里写一句话 | — | 会先联网检索（「智能搜索」勾着时），把命中的资料变成可点回原文的引用 |

几条会咬人的规则：

- **材料总字数**：合并后上限 300000 字（界面写「合并后 1029 / 300000 字（含分隔换行）」）。超了会在提交前被拦。
- **份数**：最多 50 份（面板写「来源列表（1/50）」）。
- **小于 300 字的材料不算语料**。300 字大约是"一条引用的上限"，整份材料塞得进一条引用时，
  引用就失去了"指向某处"的意义，后端于是把它降级成"主题提示 + 联网检索/模型自己的知识"。
  想要"每句话都能溯源"，材料要给足（本次实测用的 1029 字就够）。
- **带材料时「智能搜索」会灰掉**，提示改成「这次带材料，不走联网检索」——这不是坏了，
  是这次生成确实不联网。
- **不带材料时才会联网**：冷启动外部检索实测 14.8 秒（8 份材料），同一个主题第二次
  0.03 秒（缓存命中）。出处 `docs/LATENCY-BREAKDOWN.md` §四。
- **「从本轮移除」和「彻底删除」不是一回事**，见第 8 节 ④。
- **原文不会跟着导图存**。抽屉底部写着「生成时用到的来源；具体出处见各节点引用，原文未随导图保存。」
  所以换一台机器打开同一张图，能看到的只有引文本身；要回查原文，那份材料得在知识库里。

## 五、生成之后能做什么

### 5.1 看引用：四步

**【前提】** 生成时带了材料（或开了智能搜索）。没有材料就没有引用。

| 动作 | 点哪里 | 你会看到 |
|---|---|---|
| ① 这个节点有几条引用 | 节点**右上角的小数字** | 抽屉打开，选中这个节点 |
| ② 引用清单 | 右侧抽屉「来源引用（2）」 | 每条形如「文档 · 文件名 · 第 423–432 字」+ 引文两行 |
| ③ 看某一处原文 | 点那一条 | 右侧换成原文抽屉：引文 + 「第 423–432 字 · 共 1,029 字」 |
| ④ 看它在全文的位置 | 抽屉里「看上下文」 | 原文铺开，命中段黄色高亮，前后各 600 字；按钮「再读上文 / 再读下文」每次扩 1800 字，贴到全文两端时消失 |

三种降级，界面各说各的话（不是"引用坏了"）：

| 情况 | 界面措辞 | 有没有高亮 |
|---|---|---|
| 来源不在知识库里（一次性粘贴的文本、已被清掉的材料） | 「这份来源没有可回查的原文……下面只是生成时记下的摘录」 | 无 |
| 正文超过单次载入上限、引用落在没载入的部分 | 「界面一次只载入前 N 字，这条引用在第 M 字处」 | 无，且不给「看上下文」 |
| 引文在正文里逐字定位不到 | 「这段引文在正文里定位不到（逐字比对不上）」 | 无 |

出处：`docs/SOURCE-REFERENCES.md`「界面：点引用回到原文那一段」。

### 5.2 改结构

**【前提】** 有图，且这张图不是正在生成。

**先认识工具条**：单击节点，它右边浮出一条小工具条：`改 / 展开 / 删 / 色`。
（截图 `images/05-node-selected.png`）

| 想做什么 | 怎么做 | 你会看到 |
|---|---|---|
| 改这个节点的文字 | **双击**节点，或按 `F2` | 框内文字全选，直接打字覆盖，回车提交；状态行「已修改，记得保存。」 |
| 让模型改这个节点（换说法、补内容） | 单击节点 → 工具条「改」或底部「改这个节点」 | 节点旁浮出输入框「改「XX」」；写一句意图，回车提交（`Shift+Enter` 换行） |
| 加子节点 | 选中节点 → `Tab` | 新节点「新节点」出现在它下面，输入框全选，状态行「已加子节点，输入文字后按回车确认。」截图 `images/13-new-node.png` |
| 加兄弟节点 | 选中节点 → `Enter` | 同一个父下面加一个兄弟，状态行「已加兄弟节点，…」 |
| 在空白处加节点 | **双击画布空白** | 在**离那儿最近**的节点下加一个子节点，状态行「已在「设施改造」下面加了一个子节点，…（可撤销）。」 |
| 删除 | 选中节点 → `Delete` 或工具条「删」 | **整支一起删**，状态行「已删除该节点及其子节点，可撤销。」 |
| 改父 / 换位次 | **拖动**节点，松手前会画一个虚线幽灵框 | 见下表 |
| 断关系（把一支摘下来挂到中心主题下） | 拖到**画布空白处**松手 | 幽灵框画在根下面最后一位，原来的父节点上有一圈光圈，提示「断开「甲二」与「甲」的关系 · 成为一级分支」 |
| 改颜色 / 图标 | 工具条「色」，或右侧抽屉「样式」 | 8 个预设语义色 + 一个 emoji；一级分支定了色，整支继承 |

**拖动的四个方向**（默认「向右」布局时；换朝向后左右会互换）：

| 拖到 | 结果 | 你会看到（松手前的提示） |
|---|---|---|
| 目标**右边** | 成为它的子节点 | 「成为「分类标准」的子节点」 |
| 目标**左边** | 成为它的**父**（目标降一层） | 「成为「设施改造」的父节点」 |
| 目标**上面** | 插到它前面，成为兄弟 | 「插到「学工处负责志愿者招募」前面（兄弟）」 |
| 目标**下面** | 插到它后面，成为兄弟 | 「插到「学工处负责志愿者招募」后面（兄弟）」 |
| 画布**空白** | 断关系，挂到中心主题末尾 | 「断开「甲二」与「甲」的关系 · 成为一级分支」 |
| 自己的子孙上 | 拒绝 | 红框 +「在它自己这一支里，挂上去会绕成一个环」 |

拖动**落在布局给的位置**，不是手指的位置——松手之后节点是"朝手势方向吸附过去"，
不会弹回原点：因为松手前那个虚线幽灵框画的就是真实落点。

**两个曾经会咬人的地方（都已修，2026-11-27）**：

- **「算不出落点」**。手册第一版记录过：把节点挂到"第 2 层节点"下面失败 2 次，画布
  上只出现一句「算不出落点」，松手内容不变、状态行也没变；而同一手势拖到一级分支右侧
  是成功的。那是**真 bug**：画布默认只画 40 个节点，把节点挂深一层之后它在"按层铺满"
  的可见名单里往后挪、可能掉出前 40 个，而拖动预演是在**这份已经截断的视图**上算落点
  的——拿不到坐标就报「算不出落点」，松手时界面把它当成"这个落点不允许"，于是什么都
  不做（连状态行都不写）。落地路径本来会把它撑出来，所以同一个手势"预演说不行、落地
  却成功"。修法：预演与落地共用同一份视图判据（被拖节点一定在可见名单里），并且
  **"几何算不出来"不再冒充"落点不允许"**。
  实测规模：库里那棵 136 节点的真图、默认预算 40，684 种"挂到第 2 层节点下面"的组合里
  修前有 **385 种**返回这句，修后 **0 种**（`tests/defects.spec.ts` 穷举钉着）。
- **超深被拒时的说法**。导图最多 8 层，拖过去会变成第 9 层时仍然拒绝，但状态行现在把
  出路一起写了：「拖过去这一支就有 9 层了，导图最多 8 层——把这一支里最深的几层删掉，
  或者换一个浅一点的目标挂」。（第一版那句话只写了墙、没写门，所以照着读会以为
  "这个方向不支持"。）

> 上表里「断关系（拖到空白）」与「拖到自己的子孙上被拒绝」两行来自实现与
> `docs/NODE-DRAG.md` §五 的浏览器实测，**本次没有重跑**；另外四种方向的提示语都逐字复核过。

### 5.3 视图收起：数据 64 个，这一屏画 40 个

**【前提】** 只对**思维导图**生效；流程图与鱼骨图不收起。

生成完之后，画布默认只画**前 40 个节点**（按层铺满：先根、再全部一级分支、再各自的子树）。
藏起来的不是删掉，数据一个节点都没少。

| 你会看到 | 意思 |
|---|---|
| 右上「显示 40 / 64 个节点」 | 这一屏画了几个 / 数据里一共几个 |
| 节点右下 `+2` | 这个节点还有 **2 个直接子节点**没画出来；点它当场冒出 2 个（实测 40 → 42） |
| 节点右下 `−` | 这个节点的子节点正显示着；点它收回去 |
| 「全部展开」 | 一个都不藏（64 个全画，字会很小） |
| 「收起到上限」 | 一次回到 40 个 |

- **点节点本身也会开合**：它还有没画出来的孩子 → 放出来；它自己的子节点是你点开的 → 收回去；
  叶子节点 → 什么都不做，只选中。（所以"点一下看详情"这条最常用的路，画面不动。）
- **展开时画布不跳**（第 8 节 ⑤）：只把刚展开的那个节点留在视野里，缩放不变。
- **收起状态不落盘**：刷新页面、换一张图，你手动点开的那几支会回到 40 个以内。
- 40 是"认知预算"，不是"一屏看得清"的界线：仓库里那棵 136 节点的树收到 40 个之后，
  `fit-all` 的字号只有 5.3px，要到 17 个才回到 12px 的可读档。出处 `docs/VIEW-COLLAPSE.md` §一。

### 5.4 改节点内容

- **文字**：双击（或 `F2`），回车提交。
- **正文说明**：生成时模型写的 2–3 句，在右侧抽屉「详情」里只读展示。
- **我的备注**：抽屉里「我的备注 0 / 2000 · 现在是空的，不影响详情与导出」——这是你自己写的地方，
  **重新生成不会覆盖它**，也**不进导出**。
- **让模型补内容**：抽屉里「展开这一支 · 让模型给这个节点补 2–4 个子节点；结果直接落画布，标成未保存。」
- **嫌这个节点没用**：`Delete`（整支删）。想保留内容但先不显示：用 `−` 收起（数据还在）。

## 六、编辑与撤销

**【前提】** 有图。撤销退的永远是**内容**，不是视图。

**哪些操作进撤销栈、一次 `Ctrl+Z` 退到哪**：

| 操作 | 进栈 | 一次 `Ctrl+Z` 退到 |
|---|---|---|
| 改节点文字 / 改标题 | ✅ | 上一次文字 |
| 加节点（`Tab` / `Enter` / 双击空白） | ✅ | 加之前（那个空节点连同它的子树一起没了） |
| 删除（`Delete` / 工具条「删」） | ✅ | 删之前，**整支原样回来**（顺序也回来） |
| 拖动改结构 | ✅ | 拖之前（含整支的坐标） |
| 断关系 | ✅ | 断开之前 |
| 改颜色 / 图标 | ✅ | 改之前 |
| 换朝向（向右/向左/向下/双向） | ✅ | 换之前（朝向写在 `content` 里） |
| **一次「修复」**（自动并单子 / 合并重名） | ✅ | 一次 = **一步**：它一次会改掉多处（后端 `repair.py` 两段交替：先全部合并、再全部压链），`Ctrl+Z` 把它们一起退掉，不是逐条退 |
| **生成落地** | ✅ | 生成**之前**那棵树（本次实测：连按撤销退到空白画布，状态行「已撤销。」） |
| 视图收起 / 展开、适应宽度 / 全图、平移缩放 | ❌ | 这些不进栈。想退回视图就点「收起到上限」 |
| 保存本身 | ❌ | — |

**上限**：最多 **50 步**，且累计不超过 **10 MB**；超了从最旧的一步开始丢
（`frontend/src/stores/mindmap.ts` 的 `HISTORY_LIMIT` / `HISTORY_BYTES_LIMIT`）。

**「修复」在哪**：当诊断里有能自动修的三类（同级重名 `DUPLICATE_LABEL`、单子节点
`SINGLE_CHILD`、只有标题的分支 `HEADING_ONLY_BRANCH`）时，诊断面板会出现「修复」按钮，
旁边写「同级重名 2 处、单子节点 3 处」。本次实测的 20 条诊断全是"没有原文引用"，
**没有可修复项，所以那个按钮没出现**。

## 六·五、账本：这张图改过什么

**入口**：`☰` → 「节点详情」（右抽屉）→「改动记录」→ 点开。默认收着，点开才去后端读。

它读的是**已保存**的改动。刚改完还没保存的那几笔不在里面——有未保存改动时，标题下面
会明写一句「还有未保存的改动。保存之后它们才会出现在这里。」

一行一句话，长这样：

| 你看到的 | 意思 |
|---|---|
| `模型生成 · 32 个节点` | 一次生成落到了画布上，那一刻树上 32 个节点 |
| `你改短了标题：「线性回归与正则化的基本原理介绍」→「线性回归」` | 一次改文字，并标出是改短还是改长（"改短"那几条正是生成侧"标题该写多长"的证据） |
| `你换了父节点：主题 → 强化学习` | 拖动改了结构。这里给的是父节点的**名字**，不是节点 id |
| `你改了颜色：无 → 琥珀（注意）` | 颜色键已经翻成人话，不是 `amber` |
| `规则整理 · 12 处` | **一次「修复」**。它一次可能改几十处，折成一行；右边的「12 条明细」点开逐条看 |

上方那行摘要读三个数：`模型给了 32 个节点`（分母）、`图上 15 处改动`（分子）、
`1 / 1 次生成一字未改`。三个要一起读才有方向——"每张图改 2 处"和"9 次一字未改、1 次
改了 18 处"是完全相反的两种情况。

再往下那几条是**可复算的结论**：「标题普遍被改短：平均 15.0 字 → 4.0 字（1 次）」
指向生成侧写的标题偏长；「零散删掉的节点集中在第 N 层」指向初次生成挖得太深。它们只说
"发生了什么"，不说"为什么"（为什么见本文九、已知限制与 `EDIT-LOG.md` 五、）。

选中一个节点后，列表上方会出现「只看选中节点」——**"这个节点被改过几次"**的答案在这
里；而**"这个节点为什么变成这样"**不在账本里，那要去上面的「检查与建议」看诊断。

底部「共 16 条事件 · 这里 5 行」是原始条数与折叠后的行数；如果账本只读了最近一段，
会补一句「（只读了最近 200 条）」。

**账本可能没在记的时候**会多一行琥珀提示，例如「昨天存过 3 张图，0 张收到改动记录」。
正常情况下那一行**不出现**——它是故障信号，不是日常读数。

## 七、保存与导出

**【前提】** 有图。生成、改图之后都不会自动保存。

### 7.1 保存

- 入口：`Ctrl+S`，或 `☰` → 「操作」→「保存」（实测抽屉里还写着快捷键提示）
- 结果：状态行「已保存，版本 1。」；抽屉里状态提示变成「已保存」，那一行同时显示节点数、
  `dev` 标记与版本号。
- **版本冲突**：两个标签页改同一张图，后保存的那个会拿到 409，界面弹「保存冲突」让你选择用哪一版
  ——不会静默覆盖。（这一条本次没有触发，判据见 `docs/` 里乐观锁与 409 三选弹层的记录。）
- **改图名**：顶栏中间就是图名，点进去直接改（没有图时它是灰的，占位文字「新对话」）。

### 7.2 导出（四种）

`☰` → 「导出…」，选一种，浏览器直接下载文件：

| 格式 | 能用来做什么 | 能不能再导回来 |
|---|---|---|
| **JSON** | 本仓库原生序列化，字段最全（含颜色/图标/图型/阶段/关系） | ✅ **唯一能原样往返的格式**（标着「（可再导入）」） |
| **Markdown** | 缩进大纲，别人在 GitHub / 飞书里能直接看 | ✅ 能导回，**形状也认得出来**（第二行有一句 `<!-- genai-mindmap: shape=… -->` 标记）；手写的 markdown 会当树导入 |
| **OPML** | 大纲工具（幕布、XMind 等）互通 | ✅ 导回是**树**，鱼骨/流程会退化成树 |
| **PlantUML** | 画图脚本，能嵌进文档 | ✅ 同上；但正文里的 `*` 已变成 `·`、说明里的 `-->` 变成 `→`，**不可逆** |

导出里**不含**原文正文，只含引用的坐标与引文（引文是生成时记下的那一小段）。

### 7.3 导入（六种）

`☰` → 「导入」，选文件。支持：本仓库 JSON、Markdown、OPML、PlantUML、XMind（`.xmind` 新版与 XMind 8 的 xml）、FreeMind（`.mm`）。

导入前要知道三件事（出处 `docs/IMPORT.md`）：

- **只有 JSON 是无损的**。其余格式能把形状/文字读回来，但视觉字段、`role`、容器名会有不同程度丢失。
- **导入会清空引用**（`source_refs` / `source_usage`）：外部引用指向的是别人那份原文的字符位置，在新环境里不存在。
- **超限不整份拒绝**：超过 1000 节点按层序截断并给 warning；单节点超 50 子截到 50；深度超 8 截断子树。
- 有未保存改动时，**打开另一张图或导入**会先问你一句「当前有未保存的修改，打开另一张导图会丢掉这些修改，继续？」（实测）。

### 7.4 删除一张导图（不可恢复）

两个入口，都是**两段式**：

| 入口 | 第一步 | 第二步 |
|---|---|---|
| `☰` 抽屉的「历史导图」那一栏 | 那一行右边的「删除」 | 变成「确认删除」+ 底下多一行「彻底删除这张导图，连同它的改动记录。不可恢复。」 |
| 「打开…」列表（`☰` →「打开…」） | 每行右边的「删除」 | 变成「确认删除」+ 行内说明；当前打开的那张会多一句「这张图上有未保存的修改，删掉也一起没了。」 |

点下去之后：

- 列表里那一行立刻消失，状态行「已删除导图「X」，连同它的改动记录，不可恢复。」
- **删的正好是当前打开的那张** → 画布清到空态，状态行补一句「画布已清空。」；
  之后再保存会是一条**新记录**，不会写回那张已经删掉的图。
- 删的是**别人的图** → 不会发生：读是共享的、删是限主的，后端返回 403，界面显示
  「这张导图不是你创建的，只有创建者能删。想留住它的内容，可以先「导出」或「另存为」一份再离开。」
  （403 而不是 404：你**看得见**它，所以不会假装它不存在。）

**"连同它的改动记录"是什么**：那张图的编辑账本（每次改了什么、第几层、删了几个节点）
跟着一起删。账本里每一行都是"这张图上某个位置发生了什么"，图没了这些坐标就没有意义；
而界面上的「改动分布」本来就按 `map_id` 读这张表，留着孤儿行只会让统计把一张已删的图
算进去。

**没有回收站。** 要留档就先「导出 JSON」（7.2 里唯一能原样往返的那一种）。

## 八、常见问题

### ① 为什么有些节点没有引用角标？

**现象**：有的节点右上角有数字，有的什么都没有。

**实测覆盖率**（这几种口径都要看，单看一个数会误判）：

| 来源 | 覆盖率 |
|---|---|
| 本次实测（1029 字材料，64 节点） | **47 / 64 = 73%** |
| 仓库记录的薄批 / 厚批（`docs/SOURCE-REFERENCES.md`） | 薄批 78–80%、厚批 86% |
| 同一薄批三次真生成（`docs/RETRIEVAL-KEEP.md` §4.1） | 81.1% / 77.5% / 69.6% |

也就是说：**一次生成总有 1/5 到 1/3 的节点拿不到引用**，这是常态，不是这次生成失败。

**而"没引用"有两种完全不同的原因**：材料里确实没有对应句子；或者这个节点是你**手动加的**。

**界面分不出来**——数据层（`MindNode` 契约）里只有 `label` / `detail` / `source_refs`，
**没有"手动/生成"这个标记**，所以界面只能说"可能"。抽屉里的原话是：

> 这个节点没有原文引用。这张图 64 个节点里有 47 个带原文引用（73%）。
> 没有引用的节点不代表内容有错：生成时模型没在材料里找到对应句子，或者这个节点是你自己加的。

**怎么处理**：想确认某个节点有没有依据，去右侧抽屉看「来源引用（N）」；想提高覆盖率，
材料给足、别太碎（<300 字会被降级，见第 4 节）。**别指望从这个提示反推"我没加过它"**。

### ② 为什么生成一张图要等几十秒？

**现象**：点了生成之后要等 30–90 秒。

**三段实测**（20 条材料样本，单并发，出处 `docs/ACCEPTANCE-METRICS.md` §4.2）：

| 段 | 你感觉到什么 | P50 | P95 |
|---|---|---|---|
| 首帧 | "界面有反应了" | **0.09 秒** | 0.12 秒 |
| 中心主题上屏 | 画布开始生长 | 5.4 秒 | 9.5 秒 |
| 完整树落地 | 可以保存/导出了 | **31.3 秒** | 41.4 秒（无材料冷启动 74–89 秒） |

**为什么慢**：不是检索慢，是**输出量大**。一次生成是 3–4 次模型往返（骨架 / 结构 /
说明），实测口径是 **耗时 ≈ 节点数 × 0.35 秒**（三组开关对照里"秒/节点"都在 0.354–0.379）。

**怎么变快**（按收益排序，出处 `docs/LATENCY-BREAKDOWN.md` §五）：

| 开关 | 实测代价 | 建议 |
|---|---|---|
| `MINDMAP_NODE_SCALE=1` | 节点 115 → 205，耗时 41.0 → 72.6 秒（**+77%**），说明均长 89 → 75 字 | **要快就关**：关掉后耗时 **−43%**，节点更少但每段说明更长。**本仓库当前已关** |
| `MINDMAP_OPTIMIZATION_CROSS_MAP=1` | 收尾附加，不改进这次的产物 | 关（纯省）。**当前已关** |
| `MINDMAP_EXTERNAL_DEEPSEEK_SEARCH=1` | 第 6 个外部来源 | 想再省 5–8 秒就关它（只影响第一次问这个主题） |
| `MINDMAP_DETAIL_LENGTH=free` | 说明段输出量 = 全部节点 × 60–150 字 | 要快就给个上限（80 字量级），说明段近乎减半 |
| 材料给得**太长太散** | 结构那一次的输出量随节点数涨 | 材料给到"够用"（一两千字）比塞十万字快得多 |

另外：**"深度思考"开着会更慢**（它让这一次走推理模型），**"智能搜索"冷启动要 +14.8 秒**（同主题第二次 0.03 秒）。

### ③ 语音为什么传不上去？

**现象**：选了手机录的音，界面上出现红色错误；或者干脆选不到文件；或者解析一直失败。

三条独立的原因，逐条对：

1. **文件类型**：只收 `.wav`。手机默认录的是 `.m4a` / `.aac`，文件选择框里**根本选不到**
   （`frontend/src/sources/input.ts` 的 `FILE_ACCEPT` 只列了 `.wav`）。
2. **采样率**：即使是 wav，**采样率必须 8000 或 16000**（`backend/app/ingestion/asr.py`
   的 `SUPPORTED_RATES = (8000, 16000)`）。手机/电脑录音工具默认 44100 Hz，传上去会 422。
   转换：`ffmpeg -i in.m4a -ar 16000 -ac 1 -sample_fmt s16 out.wav`。
3. **服务端凭证**：语音转写走阿里云百炼 Qwen-Audio-ASR，服务端要配 `DASHSCOPE_API_KEY`；
   没配时上传 `.wav` 返回 422（`START_HERE.md` 的可选变量表第一行就是这条）。

**最省事的做法**：用页面里的 `🎤`「按住说话」。它在浏览器里录音、自己重采样成
16kHz 单声道 16bit WAV 再上传，绕过前两条（前提：浏览器允许麦克风，且走 https 或 localhost）。
第三条绕不过——那是部署方要配的。

### ④ 「从本轮移除」和「彻底删除」有什么区别？

**这是最容易点错的一处。** 2026-11-26 之前这两个按钮叫「移除」与「删除」，并排在同一行
——两个词都是"把这个东西从我眼前拿掉"的语感，而后果差一个数量级。现在名字里各带上了
范围和后果，列表上方还有一行对照说明。

| | 从本轮移除 | 彻底删除 |
|---|---|---|
| 点哪里 | 材料缩略块上的 `✕`，或材料面板里那一行的「从本轮移除」，或「清空来源」 | 材料面板里那一行的「彻底删除」→ 再点一次「确认彻底删除」 |
| 影响范围 | **只影响这一轮生成**：这份材料不再参与下一次生成 | **连知识库那份一起删掉** |
| 知识库里那份 | **还在**（仍占 200 份上限里的一个位置） | 没了 |
| 能恢复吗 | 再传一次即可（但要重新解析） | **不可恢复** |

**"要点两次"现在看得见**：材料被导图引用时，第一次点「彻底删除」后端会 409，按钮当场
变成 **`确认彻底删除`**（红字加粗），旁边多一句「再点一次即永久删除，不可恢复。」
——不再是一个看不出来的空动作。（第一次之后那一行还会写着"这份材料还被 N 张导图引用"，
那是被拒的原因，不是失败。）

界面上的原文（可逐字对照）：

```
列表上方：「从本轮移除」= 这次生成不用它，材料还在知识库里；「彻底删除」= 从知识库永久删除，不可恢复。
按钮     ：从本轮移除    彻底删除    确认彻底删除
```

**为什么必须写清**：如果只点「从本轮移除」，那份材料还留在知识库里；下次再传**同一份文件**，
因为内容哈希相同，会被**静默复用**（连上一次的标签一起），你以为"我删过了"而它还在。

### ⑤ 展开节点后为什么画布不跳了？

**现象**：点开一支，画面不动、缩放不变，只有新节点在那旁边长出来。

**这是刻意改的，不是没适配。** 以前展开一支会按"整张图"重新适配：图变大了就缩到看不清，
或者把视图锚回中心主题——用户报的就是「每次展开都会回到主节点」。现在：

- **展开一支**：只把**被展开的那个节点**留在视野里，缩放与位置都不动（新节点贴着它长）。
- **收起一支**：整张图变小了，这时才重新铺满（否则会留一屏空处）。
- **点「全部展开」/「收起到上限」**：这两个是对"这一屏画多少个"的直接表态，会立刻重排并重新适配。
- **切「适应宽度 / 全图」**：当场生效；从「全图」切回「适应宽度」会**回到你切走前那一屏**。

想让它"展开后自动适配"：那是另一条路（把 `MindMapCanvas` 里 `expandBranch` 的
`keepAround` 换成 `applyView`），当前**没有开关**，也没有计划——因为那正是被报过的那个问题。

### ⑥ 改了图之后 Ctrl+Z 能退到哪？

**一句话**：一次操作一步，视图操作不占步，修复占一步，生成本身也是一步。

- 拖动 / 删除 / 加节点 / 改文字 / 断关系 / 改色 / 换朝向：**一步一退**。
- **修复**（自动并单子、合并重名）：**一次修复 = 一步**，即使它一次改了几十处
  （实测记录里 561 节点的图一次会产生 504 条合并），也是一次 `Ctrl+Z` 全退。
- **生成落地**：也是一步。本次实测连续 `Ctrl+Z` 能一路退到空白画布，状态行写「已撤销。」。
- **收起 / 展开 / 视图档位 / 平移缩放**：不占步，`Ctrl+Z` 不会动它们。
- 上限：50 步 / 10 MB，超了从最旧的开始丢。

## 九、已知限制

如实列。这些**不是 bug 报告**，是这一版就是这样。

**它不做的事**

1. **删除导图没有回收站**。`☰` 历史抽屉与「打开…」列表里都能删（两段式：点「删除」→
   点「确认删除」，见 7.4），但删掉**不可恢复**，并且连同那张图的改动记录一起删。要留档
   先「导出 JSON」。（2026-11-26 第一版手册写的是"没有删除入口、`DELETE /api/mindmaps/{id}`
   实测 405"——那条限制已经不成立，接口与按钮都补上了。）
2. **没有实时协作、没有权限隔离**。现在是单机原型；`☰` 抽屉里有游客/登录/注册，
   登录之后导图保存到自己名下（界面原话：「登录之后：导图保存到自己名下，别的账号能看不能改」），
   但**不要直接放到公网或用于敏感数据**（这一条写在 `START_HERE.md` 里）。
3. **没有知识图谱**。`☰` →「知识库」抽屉能看到库里的材料、每份被几张图引用、点开看正文前 4000 字，
   也能删材料；但"把图谱当成一张可浏览的图"这件事没有做，`/api/knowledge/search` 只服务生成链路。
4. **不做翻译、不做模型评测、不渲染多主题/多布局**。v2 契约里的 `layout` / `theme` 字段能存能读，
   画布用一套紧凑树布局算法，朝向可选右 / 左 / 下 / 双向四种；除了「思维导图 / 流程图 / 鱼骨图」，没有别的图型。

**边界**

5. **视图默认只画 40 个节点**，而 40 个在 1600×852 上仍然过不了"一屏看清"那一档
   （136 节点那棵树上 40 个是 5.3px）。收起状态不持久化（刷新/换图就回到 40）。
6. **导图最多 8 层**。拖过去会让某一支超过 8 层时，那次拖动会被拒绝，状态行写
   「拖过去这一支就有 N 层了，导图最多 8 层——把这一支里最深的几层删掉，或者换一个浅一点的
   目标挂」。（第一版手册记的「把节点挂到第 2 层节点下面会失败 / 算不出落点」是**另一个
   问题**，真因是拖动预演读的是按预算截断后的视图树，已修，见 5.2 的那两段。）
7. **流程图 / 鱼骨图不收起、不支持跨容器拖动、阶段次序与骨的次序拖不动**。
   跨阶段改归属是"这一步属于哪个阶段"的语义，不是排版（`docs/DRAG-ROUND3.md` §二）。
8. **坐标永远是布局算的**，没有自由摆放（拖不出"我就想放这儿"）。`layout: manual` 这个字段
   在契约里留了位置，但没做——做了要付 `bounds` / `fitView` / 可读性选档 / 收起计数四笔账。
9. **节点不支持自转**。"旋转"能做的那一档是**整张图换朝向**（左上角四个按钮），已经在；
   每支一个方向、节点自转都不做（`docs/DRAG-ROUND3.md` §三）。
10. **语音只收 8k/16k 的 WAV**，且要服务端配阿里云凭证（第 8 节 ③）。
11. **一次导出的文件里没有原文**，只有引用坐标与引文；换机器打开要回查原文，那份材料得在知识库里。
12. **导入会丢东西**：只有本仓库 JSON 无损；其余格式形状会退化、引用会被清空（第 7.3 节）。
13. **诊断只报不改**（除了那三类可自动修复的）。实测一次 64 节点的图有 **20 条诊断**，
    其中绝大多数是"节点「X」没有可核验的原文引用；不代表节点内容错误"——那是提示，不是错误。
14. **tab 键盘长节点有前提**：`Tab` / `Enter` / `Delete` 只在焦点落在画布上时生效；
    点过别处（比如输入框）之后要先点一下画布。
15. **鱼骨的六个类别默认固定**（5M1E），要按主题自由定类别得开
    `MINDMAP_FISHBONE_FREE_CATEGORIES=1`（默认关，`docs/FISHBONE-CATEGORIES.md`）。
