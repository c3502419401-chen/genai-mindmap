# 提示词里那些祈使句：三问核查、10 条判定、以及一条落地的判据

> 上一轮把"提示词要求一件事、却没给它做那件事的手段"这个问题摊开了：242 处祈使句
> 里挑了 10 条，按**绕过形状**分成 A/B/C/D 四类。这一轮做三件事：把那 10 条逐条过
> 三问（有字段承载 / 有判据 / 有诊断码）、判 A 类到底该 a/b/c 哪一个、并把判下来的
> 那一条**落成代码与用例**。
>
> 本轮动到的文件：`app/optimization/service.py`（新判据 + 新诊断码）、
> `app/optimization/repair.py`（登记 MANUAL_ONLY）、`app/agent/tools.py`（只动
> `CROSS_REFERENCE_RULES` 的措辞）、`tests/test_optimization_rules.py`（7 条用例）。

## 结论先写

| 问题 | 判定 |
|---|---|
| 10 条里有几条值得补手段 | **1 条**（A 类的「另一支不写节点」）。其余 9 条：3 条不该有硬要求（C/D）、1 条实测零发生（B）、5 条已被现有码覆盖或不可确定性判定（A 的"范围不重叠"、C 的 kind） |
| A 类判 a / b / c 哪个 | **都不是**。选 **d：把"该不该删节点"这个问题换成"同一对有没有被指认"**——因为 a/b/c 的分流需要"材料里这件事出现几次"，那是判据拿不到的信息（实测：a 与 b 在树上**形状完全相同**） |
| B 类（占位句）实情 | 库里 104 个文件 / **6175 个节点**扫下来，真占位句 **0 次**；唯一的 1 次命中是「材料未提及该模型上线后的效果或规模」——那是**如实标注边界**，不是占位。这条要求是预防性的，不为它加判据 |
| C 类三条 | decision 计数、鱼骨密度**都不该补**（合法形态存在）；kind 两值**剔除**（有意不拦）。顺带发现一处真该补的：**空骨**（鱼骨某类下零原因） |
| D 类 | **不补**。候选清单已经按连接数排序并打印度数，"覆盖优先"里度数只是次要键——强行判"必须选度数前 N"会与产品策略打架 |
| 「给了手段」三条对照的共同点 | 用户的判断（执行点在代码里）**方向对，但还可以更硬**：真正的共同点是**违约的产物在数据里根本构造不出来**，不是"被检查出来"（见 §七） |
| 那 242 处里有多少该删 | 按字节算：**一条都不该删**，但很多不该被当成"约束"。108 条去重后的独立祈使句里，7 条是纯文风、47 条带可数对象（口径型）。真正的分界不是"删不删"，是"该用哪一种手段"（见 §七） |

## 一、10 条的三问核查

三问：**① 有输出字段承载吗 ② 有确定性判据能看见违反吗 ③ 违反了有诊断码吗**。
三问全否 → 登记。下表每一格都对着代码行号，不是印象。

| # | 要求（出处） | ① 字段承载 | ② 确定性判据 | ③ 诊断码 | 判定 |
|---|---|---|---|---|---|
| A1 | 「彼此覆盖的范围不重叠」 | **无**：label 是自由文本 | **无**：`CROSS_BRANCH_DUPLICATE` 只判逐字同名，判不到"范围重叠" | 有码，但**判不到这一条** | **不补码**。"范围重叠"的可判代理就是"两处是同一件事"，那正是 §二 落地的 `CROSS_BRANCH_UNLINKED` |
| A2 | `CROSS_REFERENCE_RULES`：「A 下写节点、B 下不写同一个节点」 | **有**：`relations[].source/target/kind/why` | **部分**：`_relations_from` 判端点/同父/上限/why，**不判"该不该写节点"** | `CROSS_REFERENCE_DROPPED` 只说"关系被丢了" | **本轮修**（§二） |
| B1 | 「不要写『材料中没有相关内容』」 | **无**：`detail` 是自由文本 | **否**：`MISSING_DETAIL` 只判空串（`service.py:460`） | 有码，判不到 | **不加判据**：实测 0 次（§三） |
| C1 | flowchart 每阶段 `decision` 0–2 个 | **有**：`Node.role` 是 Literal 六值 | **部分**：`FLOW_BRANCH_UNRESOLVED` 判"标了 decision 但出口没落到节点上" | 有 | **不补计数判据**：0 个 decision 的全直线流程是合法产物 |
| C2 | 鱼骨每类 2–4 条 | **有**：`bones[].root.children` | **部分**：`FISHBONE_CATEGORIES_INCOMPLETE` 判"缺骨" | 有 | **不补密度判据**；该补的是**空骨**（某类下零原因），另立 |
| C3 | `kind` 只两值 | **有**：`RelationKind` 六值 Literal | **有**：未知 kind 在 `_relations_from` 被丢（`tools.py:8647`） | 有（记进 `no_reason`） | **有意不拦**，剔除 |
| D1 | 一级分支「从连接数高的概念里挑」 | **有**：候选清单已按度数排序并打印度数（`tools.py:8406-8409`） | **无运行时判据**（只有测量脚本的"骨架忠实度"） | 无 | **不补**：见下 |

**三问全否的只有 A1 与 A2**；B1 全否但零发生；剩下的都有一半。

### 1.1 清单本身要校正一处

「彼此覆盖的范围不重叠」在 `tools.py` 里出现 **5 次，但提示词正文只有 2 处**
（`PLAN_PROMPT:3183`、`_graph_plan_ask:8566`），另外 3 处（`4336` / `10373` /
`12146`）是**注释在引用那句话**（解释"模型并不听"）。上一轮记的"4 处"把注释也算进
去了。按正文算，这一条是 2 处要求、0 处判据。

### 1.2 D1 为什么不补

`_pick_supplement`（`tools.py:9568`）的排序键是
`(-覆盖的材料数, -度数, 名字长度, 名字)`——**覆盖优先，度数只是并列时的次要键**。
所以"挑了低度数概念"本身不等于错：一份只出现一次的材料，它的概念度数低但不能不
覆盖。强行判"必须选度数前 8"会把产品策略判成缺陷。

而这条要求真正的失效形态（模型完全不看图、按模板凑分支）已经被三道闸挡住：
`GRAPH_OUTLINE_UNAVAILABLE`、`GRAPH_SKELETON_UNAVAILABLE`、`OUTLINE_MIN_COVERAGE`。

## 二、A 类：判 **d**，不是 a / b / c

### 2.1 先确认"模型没照做"这件事，以及它是怎么没照做的

三次真跑（`docs/CROSS-BRANCH-DUPLICATES.md` §八）的证据在本轮被复算了一遍：
`S02-r1/r2/r3.json` 的 **24 条 `relations`**，两端 label 的关系是——

| 采样 | relations | 两端是**同一件事的两种写法** | 两端是**真交叉引用** |
|---|---|---|---|
| r1 | 8 | 8 | 0 |
| r2 | 8 | 6 | 2（「实验考核」↔「实验安排」、「概述4学时」↔「第一部分 概述」） |
| r3 | 8 | 8 | 0 |

也就是说：**规则让模型把"同一性"说出来了，但一处都没删**。8 条线的两端全是两个已
存在的节点（§八 的原话），本轮复核一致。

### 2.2 为什么 a / b / c 都不足以落地

| 候选 | 卡在哪 |
|---|---|
| **a** 保留要求 + 给它判据（"被 references 连起来的某一端必须被删或降级"） | 判据要说清"哪一端该删"，那就得知道**材料里这件事出现几次**。这一层拿不到材料（`check()` 只收到树与 relations），做不到确定性 |
| **b** 放弃要求，改成"两支都写 + 加一条 references + why 说清" | 这是**把重复洗成特性**。r2/r3 那 14 条"两端近义"的线正是这个形态：用户仍然读到两遍同一句话，只是多了一根虚线。而"red 6 → 0"会被继续读成成功 |
| **c** 保留要求 + 把"不照做"写进文档 | 一纸空文。而且实测表明模型的"不照做"恰好是**最坏的那种**：它学会了用改写逃避判据 |

**根因**：a/b/c 的分流全都依赖同一个判断——"这个视角材料里有依据吗"。本轮实测确认
**判据拿不到它**：a 类（模型造的第二个视角）与 b 类（材料本身两处）**在树上形状完全
相同**，都是"跨支两处 + 一条 relations"。

```
S02（a 类，材料里只有一行）         S05 / S08 / S17（b 类，材料本身两处）
  课程内容与模块                       课程目标
    └ 第一部分 概述（4 学时）              └ 掌握国民经济核算口径
  学时分配                             第一章 导论
    └ 概述 4 学时         ← 同核          └ 通货膨胀率与失业率口径   ← 不逐字同
  + references（为什么）                + references（为什么）
```

任何字符串判据都分不开这两张图。**所以不要再往"判断 a 还是 b"上加智能。**

### 2.3 d：把问题换掉

> 不判"该不该删"，只判"这一对**有没有被指认**"。

- 有 `relations` → 模型已经把"这两处是什么关系"写成了可读的一句话，读者不必猜。
  b 类（材料两处）在这里是**合法**的，它本来就该保留两个视角。
- 没有 `relations` → 图上两处同一件事，读者要自己判断，而图里没有任何线索。**这就是
  缺陷**，且它对 a 与 b **都成立**（b 类不指认也是缺陷：读者会以为那是两件事）。

于是判据不需要知道材料，只需要知道"同核 + 无声明"。而"同核"是字符串判据能做的。

### 2.4 落地：`CROSS_BRANCH_UNLINKED`

判据（`optimization/service.py`）：

1. `_core_label(label)`：**先剥序号前缀**（`第一部分` / `第 3 章` / `M2：` / `一、`）
   **与量化尾缀**（`4 学时` / `7 次` / `30%`），**再**归一化标点空白全半角。
2. 所有"直接父不同、且不在同一条祖先链上"的节点对里，`core` 相同
   （且 `len(core) ≥ 2`）→ 一对。
3. 这一对若**没有**任一方向的 `relations` → 计入。
4. 聚合成**一条**汇总 warn（S02 一次能出 8 对，逐对报会淹掉面板）。

四条边界，每条都对着一次实测误报：

| 边界 | 挡掉的是 |
|---|---|
| 同父不算跨支 | 同级的重复是 `DUPLICATE_LABEL` / `NEAR_DUPLICATE_LABEL` 的地盘 |
| 祖先链不算跨支 | S07 的「力矩与转动定律」父子同名——要改的是层级，不是加一条线 |
| 归一化后逐字相同的**不报** | 那一档归 `CROSS_BRANCH_DUPLICATE`。**这条是本判据存在的理由**：它只报"被改写成近义"的那一档 |
| `core` 剥空则退回归一化原文 | 否则「第二章 8 学时」与「第五章 6 学时」都剥成空串、空串相等 → 互为同一件事 |

**为什么不是相似度阈值**（这是本轮最重要的一次否定）：2-gram Dice ≥ 0.5 那一版在
库里 28 棵树上跑过——**假阳性 210 对、真命中 22 对**：

```
真命中   「内核模块编写4次」↔「内核模块编写」        dice 0.91
假阳性   「第二章 8 学时」↔「第五章 6 学时」        dice 0.50   ← 并列项
假阳性   「WebSocket」↔「Socket 编程」              dice 0.67   ← 一个是另一个的子串
假阳性   「宏观经济学课程大纲」↔「宏观经济学研究对象」dice 0.50
```

中文短标题上，Dice 度量的是"共享几个二字组"，而"同一件事"的信号其实是**结构性的**：
序号与数量是装饰，去掉之后剩下的是不是同一句话。

### 2.5 判据在库里的实况

`check()` 跑库里 28 棵树（`backend/data/acc_trees*`）：

| 树 | relations | 旧口径 red（逐字） | `CROSS_BRANCH_UNLINKED` |
|---|---|---|---|
| S02（加规则前，68 节点） | 0 | 6 | **0**（全逐字，归 `CROSS_BRANCH_DUPLICATE`） |
| S14（c 类误报样本） | 0 | 2 | **0**（三候选人的「项目经历」逐字同名，被逐字档挡掉） |
| S05 / S07 | 0 | — | 1 / 5 |
| **S02-r1（加规则后）** | 8 | **0** | **1** |
| **S02-r2** | 8 | **0** | **2** |
| **S02-r3** | 8 | **0** | **0** |

**r1 / r2 / r3 那一列就是这条判据的全部意义**：red 已经是 0/0/0，而"同一件事写了两处
且没有任何指认"仍有 1/2/0 处。上一轮的 `[red 6→0]` 会被读成成功，这一轮它能被读出
"还剩几处没交代"。

r2 那 2 处还有个额外解释：它写了 8 条关系、**正好顶到 `CROSS_REFERENCE_MAX = 8`**，
两条同核对被挤掉了。这是"上限"这个手段与"要指认"这个要求之间的冲突——**本轮不改
上限**（8 是画布口径），但把它变成可见的（2 条 warn），并在提示词里加了"优先给同核
对写关系"。要改上限，先要有"8 条够不够"的实测，而目前只有一个采样。

## 三、B 类（占位句）：查了，是 0 次

`backend/data` 下 104 个树文件 / **6175 个节点**，扫 label 与 detail，正则覆盖
「材料中没有相关内容」「材料未提及/涉及/覆盖」「未检索到」「无相关内容」「没有找到」
「缺少资料」等 9 种形态：

```
文件=104  节点=6175  命中=1
S14.json  detail  node='检索排序模型微调'
  「…说明其在模型训练与调优层面有实际动手经验，但材料未提及该模型上线后的效果或规模。」
```

**那 1 次不是占位句**：它在标注"这条经历的边界在哪"，是有信息量的。真正的占位句
（用一句话替代内容）**0 次**。

结论：这条要求是**预防性**的（`BRANCH_NO_EVIDENCE_RULES` 写它的场景是"这一支这次
没检索到"），库里没有发生过。按"先查有没有发生过，再决定要不要补"的原则——**不补**。

顺带一个反向确认：宽正则（加上「待定」「待补充」）会命中 S11 的 9 处「报价待定」
「部署方式待定」——那些是**真实内容**（会议纪要里确实待定），说明这条判据一旦做宽，
就会把"材料里就是未定"判成"模型偷懒"。这也是不为它加判据的第二条理由。

## 四、C 类三条：两条不该有硬要求，一条剔除

| 要求 | 判定 | 理由 |
|---|---|---|
| `decision` 0–2 个 | **不补** | "0 个"的流程图是合法产物（全直线审批流、单路径 SOP）。真正该报的是"标了 decision 却只有一个出口"，而那条已经有码（`FLOW_BRANCH_UNRESOLVED`）。给"密度"建判据的代价是每张直线流程图都被喊一次，用户很快学会忽略诊断 |
| 鱼骨每类 2–4 条 | **不补** | "1 条骨在某些主题下也对"（用户的原话，同意）。密度是写作建议 |
| `kind` 只两值 | **剔除** | `RelationKind` 六值是契约值域，提示词只是要求"在这条路上只用两个"——属产品口径，不是缺陷 |

**但顺带查出一处真该补的**：`_fishbone_shape_diagnostics`（`tools.py:8090`）只数
"六类里缺哪几根"，**不数"某一根骨下面零条原因"**。空骨在画布上是一根光骨头，是
用户可见的坏结果，且判据完全确定性（`bone.root.children == []`）。它不在那 10 条里，
本轮**不动**（不扩大到清单外），记在这里作为下一条候选。


一个关于世界的问题降级成一个关于字符串的问题：这件事模型判得准，判据也看得见。
再配一句"上限不够时宁可合并"，把 `CROSS_REFERENCE_MAX` 那个冲突的出口说清。

## 七、自评：三条对照的共同点，以及"该删多少"

### 7.1 用户的判断方向对，但还可以更硬

用户判：**执行点在代码里，不在提示词里**。对。但三条对照的共同点比这个更强：

| 对照 | 违约的产物长什么样 |
|---|---|
| `why` 必填 | **不存在**：`_relations_from` 把没有 why 的边丢掉，产物里没有"无 why 的边" |
| 上限 8 条 | **不存在**：排序截断之后，第 9 条边不在产物里 |
| `role` 六值 | **不存在**：`Node.role` 是 Literal，写第七个值 → 422，产物根本存不下来 |

三条的共同点不是"检查得严"，而是——

> **违约的产物在数据里构造不出来。**

这个表述比"执行点在代码里"多出两件事：

1. 它给出一个**可操作的检验**：先问"违约的东西能不能被存下来"，而不是"有没有判据"。
   有判据但违约产物可构造（`MISSING_DETAIL` 之于占位句、`CROSS_BRANCH_DUPLICATE`
   之于近义改写）——那就是**看得见但拦不住**，正是这一轮修的形态。
2. 它说明了**为什么提示词永远做不到第三条**：`relations` 是可选字段（不写就是空
   数组），出口不唯一。所以任何以 `relations` 为出口的要求，**最多能做到"可检查"**，
   做不到"不可构造"。想把"另一支不写节点"变成不可构造，唯一的办法是让"同一件事写
   两处"这件事**没法被表达**——而那需要契约层知道"哪两处是同一件事"，也就回到了
   判据拿不到的那个信息。

所以我的结论是：**"执行点在代码里"是手段，"违约产物不可构造"是判准；前者是后者的
实现方式之一，而更多时候只能做到"违约产物可构造但被看见"。**

### 7.2 那 242 处里有多少该删

先给口径（本轮机械统计，可复算）：`tools.py` 里 38 个提示词常量、13 510 字，按
`。！？；\n` 切句、只留 ≥12 字且带祈使动词的——**120 条**，去重后 **108 条**（12 条是
同一句在两三个常量里各写一遍，例如「原文与你的知识冲突时按原文写」在三个
`DETAIL_ONLY_*` 里各一次）。与用户的 242 差在范围（我只算 `tools.py`，他大概连
`generation/`、`knowledge/`、`importing/` 一起算）与切分粒度。

**判定：一条都不该"删"——该删的极少，该"降级"的很多。**

理由：这些句子里，大部分不是"要求"，是**同一件事在第 3 次被重述**（位置即权重：
system 里说不动的，挪到 user 末尾贴着输出位置就动了，`tools.py:11011` 有实测记录）。
把重述删掉不会让模型更守规矩，只会让它少一个提醒。

真正该做的分档是这三类，而**不是"给每一条配诊断码"**：

| 类型 | 识别特征 | 该用什么手段 | 只写提示词的后果 |
|---|---|---|---|
| **口径型** | 有可数对象、取值域、必填/不得为空 | 契约（`Literal` / `Field` / 校验）或判据 | 只是**预告**：模型不知道边界在哪，代码也不拦 |
| **动作型** | "先做 A 再做 B"、"超了该干什么"、"哪种情况用哪种写法" | **只能**写在提示词里，但触发条件必须是模型能判的**字符串/结构**，不能是"世界状态" | 空文（A 类那条的前一版就是：要求它判断"材料里有没有第二个视角"） |
| **文风型** | 措辞、长短、语气、编号、口语化 | 提示词，不建判据 | 无害；建判据就是**过度工程** |

按这个分档回看统计：**7 条纯文风**（「不要编号」「不要写成名词短语」这类）——给它们
建判据等于给编辑器装语法警察；**47 条带可数对象**——本该由契约执行的，其中一部分
已经由契约执行了（`role`、`kind`、`children` 层级），**剩下的才是"该补手段"的真候选**。
`decision` 密度、鱼骨密度属于"有可数对象但不该硬性执行"的子类（合法形态存在）。

**所以"给大部分补手段"确实是过度工程**，但原因不是"大部分是写作建议"，而是：
**大部分要求要么已经由契约执行、要么是重述、要么是不可确定性判定。** 真正的判据是
一句话：

> 一条要求值得补手段，当且仅当 ①它有可数对象或可判定形态（不是"世界状态"），
> ②违反后的坏结果**用户看得见**，③这个坏结果**能被确定性判据从产物里读出来**。

三条全中才做。本轮 10 条里全中的只有 1 条（A2），这就是为什么只落一条。
