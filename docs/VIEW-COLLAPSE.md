# 视图层收起：数据完整，这一屏默认不摊开

折叠退休之后（`7d25a85`）数据层是完整的一棵 100+ 节点的树，可它整棵摊在 1600×852 上
是**不可读的**：`fit-all` 的字号只有 1.6–3.1px。这一轮把可读性交回渲染层——
**数据一个节点不动，画布按层少画几层，每个被收起的节点留一个「还有 N 个」的入口。**

它和折叠的区别只有一条，但它是全部：

| | 折叠（`_fold_tree`，已退休） | 收起（这一轮） |
| --- | --- | --- |
| 数据 | 子树被并成一个叶子，节点**没了** | 一个节点都不动 |
| 保存 / 导出 / 撤销栈 | 只剩下折叠产物 | 与收起之前逐字节相同 |
| 还原 | 恢复不了（`node_expand` 是重新生成一条新分支） | 一次点击 / 一个按钮 |
| 出现在哪 | 生成侧（`backend`） | 渲染层（`frontend/src/canvas/view-collapse.ts`） |

## 一、读数：整棵 vs 收起一层

三棵真树从 `backend/data/mindmaps.db` 与 `runs.candidate` 原样导出（见
`frontend/tests/fixtures/real-trees.ts`），视口 1600×852，`NODE_SIZE = 180×48`、
层距 236、兄弟间距 20。

| 树 | 全展开 | 展开到 2 层 | 展开到 1 层 |
| --- | --- | --- | --- |
| 136 节点 / 6 支 / 深 4 | 136 个 · 1124×6236 · fit-all **0.114 → 1.6px** · 默认档 112 个在视野外 | 25 个 · 652×1204 · 0.59 → **8.3px** | 7 个 · 416×388 · 1.83 → **25.6px** |
| 95 节点 / 4 支 / 深 3 | 95 个 · 888×4944 · 0.144 → **2.0px** · 75 个在视野外 | 22 个 · 652×1136 · 0.625 → **8.8px** | 5 个 · 416×252 · 2.817 → **39.4px** |
| 80 节点 / 8 支 / 深 3 | 80 个 · 888×3244 · 0.219 → **3.1px** · 53 个在视野外 | 33 个 · 652×1612 · 0.44 → **6.2px** | 9 个 · 416×524 · 1.355 → **19.0px** |

两个口径别混：

- **算术值**是 `fitAllScale` 的原始输出（`tests/view-collapse.spec.ts` 断言的与
  `canvas-viewport.spec.ts` 一致的量）；
- **用户看到的值**还要经过 `MAX_ZOOM = 1.6` 夹取——所以 1 层那两棵（1.83 / 2.82）
  实际停在 1.6，字号 22.4px。两条路径都不低于 12px。

判据是 `MIN_READABLE_SCALE = 12 / 14`。**"2 层 + 根"过不了这一条**（6.2–8.8px），
所以默认值是 1（根 + 一级分支），不是 2。这不是审美选择，是算术结论：正整数层数里
1 与 2 之间没有第三档。

宽度一直不是瓶颈（最大 1124 < 1600），**高度是**——75 个叶子沿竖轴摊开就是 6236px。
所以"按层少画几层"立竿见影，"缩得更小"只会让字更小。

## 二、过滤口径

```
显示某节点的子节点  ⟺  子节点层号 ≤ expandDepth  或  这个节点被用户点开过
```

- **层号不压缩**：收起第 3 层不会让第 4 层升到第 3 层（`depth` 还是配色继承、面包屑、
  `data-node-depth` 的依据）。
- **只作用于树型**。鱼骨与流程的画布树是合成出来的（虚拟根 + 每个容器一个子），本来
  就是"一层容器 + 一层节点"，收起没有收益，层号口径也不同。
- **生成中的预览不收起**：那一刻要的是"节点一个一个长出来"的反馈。
- **「还有 N 个」的 N = 直接子节点数**，点一下当场冒出这么多。整支的规模放在 `title`
  与 `aria-label` 里（"整支 17 个节点"）。写 18 而只冒出 3 个，这个数第二次就没人信。

默认值不是写死的 1，而是**跟着视口自适应**（`chooseExpandDepth`）：

```
从全展开往下试，取第一个"fit-all 缩放 ≥ MIN_READABLE_SCALE"的层数；
全展开就达标的（小图）返回 Infinity —— 一个节点都不收起。
```

判据与 `clarity.chooseViewMode` 是同一条算术，只换了自变量（那边问"哪一档视图"，
这边问"展开到第几层"）。共用一条判据的理由很实际：分两处写就会出现"收起之后自动切到
全图档、字仍然只有 8px"这种两句话都成立、画面却读不出来的状态。

这也回答了"默认收起会不会让 7 节点的树也只剩 1 个节点"：不会。**装得下就不收**，
小图在这个功能上完全隐形。

## 三、与 undo / 拖拽 / 保存导出的交互

**① 收起/展开不进撤销栈，也不置脏。** 它是视图状态，存在 store 的三个
`ref` 里（`expandDepth` / `viewExpandedNodes` / `viewDepthPinned`），不碰 `content`。
`undoDepth` 不变、`dirty` 不变、`clientRevision` 不变。Ctrl+Z 撤的永远是内容——
用内容撤销去退视图，用户会发现"撤销一步"把刚改的字也吃了。

**② 被藏起来的节点被 undo 恢复时：按当前口径重新算，不特判。** 视图的规则是"层号"，
不是"这次操作"。撤销一次删除之后如果恢复出来的那几支仍在折叠点后面，画的仍然是
折叠点——但**折叠点上的数字会变**（`foldedChildren` / `foldedSubtree` 都是 computed）。
不额外把它展开，是因为 undo 的语义是数据回退，不是"聚焦到刚才那一下"。

**③ "选中即可见"是硬不变式。** 选中 / 开始编辑 / 新增节点 / 从引用列表跳转，都会先把
目标节点的祖先链放进 `viewExpandedNodes`（`revealInView`）。理由只有一个：不许出现
"详情面板正在说一个画布上看不见的节点"。按 Tab 加子节点后画面毫无变化也是同一类 bug。

**④ 拖拽：这个仓库里没有。** `MindMapCanvas` 的 `<VueFlow>` 写死
`nodes-draggable="false"`，`store.nodes` 里 `draggable: false`；`Node.pos` 在渲染层
**没有任何读者**（全仓只在 `api/types.ts` 与生成的 `schema.d.ts` 出现）。所以不存在
"用户拖了一个可见节点，坐标存哪、展开时怎么回来"这个问题——坐标只有一个来源：
`layoutDiagram`。展开/收起后整棵树重排是**必然且正确**的（布局是纯计算的，没有"用户
记住的位置"可保）。`tests/view-collapse.spec.ts` 用一条用例把这个事实钉住了，免得
下一轮有人按"拖拽存在"的前提写代码。

**⑤ 保存 / 导出 / 导入：收起状态不落盘，也不该落盘。**

`Node.collapsed` 在契约里（`backend/app/contracts/mindmap.py`），FreeMind 的
`FOLDED="true"` 与 JSON 导入都会写它，前端目前只透传保存。**这一轮没有用它做持久位**，
四条理由：

1. 它已经有主：导入的文件用这一位表达"这个节点在源文件里是收起的"。视图收起往上写，
   等于覆盖导入信息，且导出时把"我这台机器上怎么看的"写进别人的文件。
2. 写 `content` 会让一个视图动作变成内容改动：`dirty` 变真（顶栏亮"未保存"）、
   `pushHistory` 要压栈（不收进撤销栈就得特判）、`clientRevision` 递增（生成冲突判定
   会因此误判"内容变了"）。
3. `diffEdits` 的 `EditField` 只有 `label / title / detail / note / color / icon`
   ——`collapsed` 变了不会被记进改动账本。内容变了、账本看不见，账本就不再是账本。
4. 展开层数**依赖视口**：13 寸屏与 4K 屏上正确的层数不同。它是"这一屏怎么看"，不是
   作品属性。把它固定在文件里，换一台机器打开就是错的。

代价要说清：**刷新页面 / 换一张图，手动点开的那几支会回到默认。** 这一轮接受这个代价
（存它需要一个新的持久层，而全仓目前一处 `localStorage` 都没有；为一个视图偏好引入
一层存储、一套清理规则与一组测试，收益不抵）。

## 四、"还有 N 个"要做到什么程度才算告诉了用户

折叠退休的理由是"别替用户决定他看什么"（`docs/FOLD-RETIRED.md` §1：`其他 4 项`
吞掉 38 个节点，点「展开」还拿不回来）。**默认收起同样是一种替用户决定**，区别只在
它可逆、且不删数据。所以披露不能停在"可点开就行"，三条必须同时在场：

1. **节点上的「+N」，常驻**。不做 hover 才淡入——鼠标扫过画布得到的印象必须是
   "这里还有东西"，而不是"树就这么大"。数字是直接子节点数（点一下兑现得了），
   整支的规模在 `title` / `aria-label` 里。
2. **画布上的总量**：`显示 7 / 136 个节点`。两个数摆在一起，用户才知道比例；只给 7
   会以为树小，只给 136 会找不到那 129 个。这行是常驻的（只要收起了东西）。
3. **一个全局出口**：「全部展开」，点完这一屏就是整棵树；全展开之后同一行变成
   `显示全部 136 个节点` + 「收起深层」，回程路一直在。

还不够、但这一轮明确不做的两件事：

- **没有"按支持久展开"**：用户展开一支、再刷新，会回到默认（见 §三 ⑤）。
- **没有分组标题**：真正好读的做法是"一级分支下显示 3 个代表 + 一个概括标题"，
  那需要模型概括（`docs/FOLD-RETIRED.md` §5 记过实测：一条批量调用 1.87 秒 / 5 组）。
  这一轮只做"少画几层 + 说清少画了多少"，不引入那次调用。

一句话的自我判定：**这一轮没有替用户决定"他看什么"，只决定了"先给他看哪一层"，
并且把另外 129 个的存在、位置和打开方式都摆在同一屏上。** 与折叠的分水岭是
"能不能一键看回原样"——能，就是视图；不能，就是删数据。

## 五、代码地图与回滚

| 位置 | 干什么 |
| --- | --- |
| `frontend/src/canvas/view-collapse.ts` | 纯函数：`viewTree()`（视图树 + 折叠计数）、`chooseExpandDepth()`（按视口选深度）、`countSubtree` / `depthOf` |
| `frontend/src/stores/mindmap.ts` | `renderSource` 里套 `viewTree`（**唯一入口**：`layout` 与 `flatNodes` 都吃它的输出）；`expandDepth` / `viewExpandedNodes` / `viewDepthPinned`；`expandNodeInView` / `expandAllInView` / `collapseViewToDefault` / `applyAutoExpandDepth` / `revealInView` |
| `frontend/src/canvas/MindMapCanvas.vue` | `applyAutoDepth()`（在 `scheduleFit` 里按视口定深度）+ 右上角那行「显示 X / Y」与两个按钮 |
| `frontend/src/canvas/MindNode.vue` | 节点右下角的「+N」角标（`data-test="node-folded"`） |

收起必须发生在 `renderSource` 而不是渲染组件里：`nodes` 与 `edges` 都从 `layout`
读坐标，而 `layout` 吃 `source.root`。只过滤 `flatNodes` 的话，被藏起来的节点仍然参与
`layoutTidy` 的占位——它们照样撑开画布、照样把字号挤到 5px，只是看不见。

**回滚路径**：把 `expandDepth` 设成 `EXPAND_ALL_DEPTH`（`Infinity`）就是加收起之前的
行为，一个节点都不藏。三种到达方式：点「全部展开」、`store.expandAllInView()`、
把 `DEFAULT_EXPAND_DEPTH` 改大（视口宽到装得下时 `chooseExpandDepth` 自己就会返回全展开）。

## 六、这一轮的验收读数

| 验收项 | 结果 | 钉在哪 |
| --- | --- | --- |
| 收起前后可见节点数 | 136 → **7**（95 → 5，80 → 9） | `tests/view-collapse.spec.ts` |
| 收起前后 fit-all 字号 | 1.6px → **25.6px**（夹取后 22.4px） | 同上 |
| 点开一个折叠点 | 7 → 10，重排后 **0 对重叠** | 同上 |
| undo | 内容回退、展开状态不动、`undoDepth` 不受视图动作影响 | 同上 |
| 保存 / 导出 / 导入 | `JSON.stringify(content)` 收起前后**逐字节相同** | 同上 |
| 全展开逐像素一致 | `store.nodes` 的每个 `position` 与 `layoutDiagram(原树)` 逐一相等 | 同上 |
| 界面披露 | 「显示 7 / 136 个节点」+ 6 个「+3」角标 + 「全部展开」 | `tests/view-collapse-canvas.spec.ts` |

## 七、已知边界（不要当成 bug 修）

- **一个根挂 50 支**（库里那棵 561 节点的探针树）收到 1 层仍是 51 个节点、仍然装不下。
  层数这个旋钮在 1 就到头了，剩下的交给已有的「适应宽度」（拖动平移）。要真正解决它
  需要分组标题（§四）。
- **鱼骨 / 流程图不收起**：它们的节点本来就少（一份 43 节点的流程图收回不了多少），
  而合成树让"层号"这个概念在两种形状下不通用。
- **并发生成时不该有人改 `expandDepth`**：`applyAutoExpandDepth` 会跳过 `viewDepthPinned`，
  但预览帧不经过收起，所以生成过程中的画布与今天完全一样。
